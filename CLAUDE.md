# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project Overview

Next.js 16 (React 19) + Tauri 2.9 + Capacitor 8 + TypeScript + Tailwind v4 + shadcn/ui + Zustand. One static export (`out/`) feeds three shells: browser (`pnpm dev`), Tauri desktop (`pnpm tauri dev`), Capacitor mobile (`pnpm mobile:sync`).

## Working Rules

Hard rules. They override any default behavior. The end-to-end pipeline (idea → brainstorm → grill → plan → build → preflight → gates) lives in [`WORKFLOW.md`](./docs/development/WORKFLOW.md). Follow it for any non-trivial change.

1. **Research before implementing.** Search `lib/`, `components/`, `hooks/`, `src-tauri/`, and the relevant ADR before writing new code. Reuse, don't reimplement. A new utility/component/hook needs proof (grep results or paths) that no equivalent exists. Start with the Subsystem Map and Cross-cutting hooks below.
2. **No simplifications.** Implement the full behavior. No stubs, mock-outs, `// TODO later`, or stripped error handling / validation / edge cases. If something cannot be implemented now, surface the blocker. Never silently degrade scope.
3. **Every component ships with a unit test.** Any new file under `components/**`, `hooks/**`, `lib/**`, `src-tauri/src/**`, `crates/<crate>/src/**` (excluding `components/ui/`, `components/ai-elements/`) needs a co-located `*.test.ts(x)` / in-file `#[cfg(test)]`. Enforced by `pnpm audit:colocated-tests`. Editing an existing component? Update its tests in the same change. **Coverage is opt-in**: never run `pnpm test:coverage` or enforce a coverage threshold unless the user explicitly asks for it.
4. **Every frontend component is i18n-wired.** No hard-coded user-facing strings in `.tsx` (aria labels, placeholders, toasts, and error messages count). Use `useTranslations()` / `getTranslations()` from `next-intl`. Add keys to the **split sources** `i18n/messages/{en,zh-CN}/**` for both locales, then run `pnpm i18n:build`. The aggregates `i18n/messages/{en,zh-CN}.json` are generated, never hand-edited. `pnpm lint:i18n` checks parity against the baseline.
5. **Language convention.** Internal narration (status updates, rationale, summaries, code comments) in **English**. Questions to the user (clarifications, `AskUserQuestion`, confirmations) in **Chinese**.
6. **Changeset for every user-facing change.** Run `pnpm changeset`, select **`cognia-next`**, pick the bump (`patch` fix / `minor` feature / `major` breaking), write a one-line summary, and commit the `.changeset/*.md` with the code. Skip only for internal-only work (tests, refactors, docs, chore, CI). Release is local-only: `pnpm release:version` bumps the root version, updates `CHANGELOG.md`, and syncs every app artifact via `version:sync`. Only the root is Changesets-managed. Do not add a publish step or release Action without asking.
7. **Label intentional dormancy on all three axes.** Documented at the type, labeled inert in the UI, and pinned by a test. Any two of three is a latent bug.
8. **The working tree is shared. Only touch your own changes.** Several sessions edit this checkout concurrently. Every git command names explicit paths this task modified.
   - **Commit** with `git commit --only <paths>` or `git add <paths> && git commit`. Never `git add .` / `-A` / `-u`, `git commit -a`, or stage a whole directory.
   - **Never run tree-wide state commands**: `git stash` (any form), `git checkout -- .`, `git restore .`, `git reset --hard`, `git clean`, `git rebase`, `git merge`, `git revert`, branch switches. They destroy other sessions' uncommitted work.
   - **Need a clean view?** `git show HEAD:<path>`, `git diff -- <path>`, or a separate `git worktree add`. Never reset this one.
   - **Before committing**, check `git diff --cached --name-only` and drop anything you did not author. A gate failing on someone else's file is pre-existing. Report it and move on.
   - **`--no-verify` is banned.** A failed hook means fix your own files and make a new commit.

## Development Commands

```bash
# Frontend (port 3000)
pnpm dev / build / start / lint / lint:fix / format / format:check / typecheck

# Jest (co-located *.test.ts(x)); two projects: pure-.ts suites under
# lib/stores/cli/packages/types/plugins/i18n run in `node`, everything else
# (and any `/** @jest-environment jsdom */` .ts, needed for Dexie/getDb,
# localStorage, window stubs) runs in jsdom
pnpm test / test:watch
pnpm test:changed            # only suites affected by your diff vs origin/dev
pnpm test -- path/to/file.test.ts

# Playwright E2E (tests/e2e/)
pnpm test:e2e                # against the dev server
pnpm test:e2e:build          # NEXT_PUBLIC_E2E=1 static export → out/
pnpm test:e2e:static         # against the prebuilt out/ (run test:e2e:build first)
pnpm test:e2e:changed        # only specs affected by your diff vs origin/dev

# Shells
pnpm tauri dev / build / info
pnpm mobile:sync / mobile:open:ios / mobile:open:android   # after `pnpm build`

# Docs (Fumadocs, port 3001)
pnpm docs:dev / docs:build / docs:start
# Marketing website: https://github.com/cognia-labs/cognia-website (separate repository)

# Gates
pnpm audit:colocated-tests   # co-located test rule
pnpm audit:rust-architecture # Rust layer map, tauri-free crates, app-shell module list (ADR-0196)
pnpm audit:sidecar-architecture # sidecar src/ layers, no import cycles, public surface (ADR-0197)
pnpm audit:slots             # plugin slot manifest audit
pnpm audit:modules           # module ownership, direction, generated registries, cycles, size, vendor neutrality (ADR-0250 §14)
pnpm lint:i18n               # i18n key parity vs baseline (lint:i18n:baseline rewrites it)
pnpm i18n:build              # regenerate en.json / zh-CN.json from split sources (`:check` to verify)
pnpm sidecar:test            # node --test on sidecar/ (separate Node project, not Jest); `:live` runs *.live.test.*
pnpm sidecar:typecheck       # standalone strict tsc over the sidecar's TypeScript (ADR-0197)
pnpm build:packages          # standalone tsup build of the zero-`@/` packages; run after ANY
                             # types-shim extraction: a child tsconfig's `paths` REPLACE the root's

# shadcn/ui ("new-york", RSC)
pnpm dlx shadcn@latest add <component>

# Storybook (preview only: stories are NOT tests and don't satisfy Rule 3)
pnpm storybook / build-storybook
```

`predev` / `prebuild` stage bundled assets (Monaco, OCR, built-in plugins/skills, sidecars) via `scripts/build/*`. Never copy or import those assets by hand. The Storybook MCP server in `.mcp.json` only works while `pnpm storybook` is running.

## Architecture

| Package  | Path      | Port | Mode                                                        |
| -------- | --------- | ---- | ----------------------------------------------------------- |
| Main app | `/`       | 3000 | static export (`out/`), consumed by Tauri **and** Capacitor |
| Docs     | `docs/`   | 3001 | static export (`docs/out/`, Fumadocs), Cloudflare Pages     |
| Mobile   | `mobile/` | none | Capacitor 8 shell over `../out`                             |

Install from repo root only (single `pnpm-lock.yaml`). `sidecar/` is a separate Node project with its own lockfile, not a workspace member.

- `app/` App Router, static-exported. `app/api/` does **not** exist at runtime. Anything needing an HTTP server lives in Tauri Rust (axum).
- `components/ui/` shadcn (no tests). `components/ai-elements/` vendored (no tests). `TooltipProvider` is mounted in `components/runtime/app-runtime.tsx`.
- `lib/utils/index.ts` (`@/lib/utils`): `cn()` = clsx + tailwind-merge.
- `i18n/`: next-intl via `withNextIntl("./i18n/request.ts")` in `next.config.ts`. Split sources under `messages/{en,zh-CN}/`, aggregates generated.
- `plugins/`: in-tree first-party plugins loaded by the plugin manager, not npm packages. This tree stays the source of truth; [cognia-labs/cognia-plugins](https://github.com/cognia-labs/cognia-plugins) imports it with history (`scripts/sync-from-host.sh` there) and builds, tests and produces the same artifact set without this checkout (`docs/plans/2026-10-30-plugins-repository-extraction.md` §27). Plugin changes land here. Any change to the plugin SDK/UI/contract sources, `types/plugin`, `app/globals.css` or `pnpm-lock.yaml` invalidates the authoring kit pin `lib/plugin/distribution/authoring-kit.json`: rebuild it from a clean checkout (§26), publish the kit on that repo's `authoring-kits` branch and bump its `authoring-kit.lock.json`.
- **Services live in [cognia-labs/cognia-services](https://github.com/cognia-labs/cognia-services)** (signaling, share, status, identity, sync, update, diagnostics, Logto mail), with the wire contracts they share with the app (`cognia-signaling-core`, `@cognia/sync-protocol`, `@cognia/status-contract`). The app pins ONE revision in `integrations/cognia-services.json`; Cargo, both `package.json`s and both lockfiles must name it (`pnpm cognia-services:check`). A contract change lands there first, then a pin bump here. `pnpm cognia-services:fetch` checks the pinned revision out under `.cache/cognia-services` for the suites and smokes that read service sources (`COGNIA_SERVICES_ROOT`). Only `services/workspace-runtime/` (bundled by the desktop) stays in this repo.
- `sidecar/`: Node sidecar bundled by Tauri. Layered strict TypeScript under `sidecar/src/<layer>/`, run unbuilt by Node (ADR-0197). Root `sidecar/*.mjs` files are launchers whose paths are a contract.
- `src-tauri/`: Rust backend, `frontendDist: ../out`. Shared crates under `crates/`.
- `docs/`: import `@/lib/source` and `collections/server` (alias → `.source/`, generated by `pnpm docs:dev` / `docs:build`).
- Styling: Tailwind v4 via `@tailwindcss/postcss`, oklch CSS vars in `app/globals.css`, class-based dark mode (`@custom-variant dark (&:is(.dark *))`).
- Aliases: `@/*` → repo root. `@cognia/*` → `packages/*/src`.

### Cross-cutting hooks (reuse, don't reinvent)

- **PII redaction**: `packages/redact/src/index.ts:hasNoLeakingPii` gates every LLM/embed call (key in `lib/twin/ingest/redaction-key.ts`). Used by Twin, Goal, Connector auto-mode (`lib/connectors/ai-loop/safe-send-prompt.ts`), Agent Team shared memory.
- **Quiet hours**: `isInQuietHours` / `msUntilQuietEnd` from `lib/connectors/outbound-runner.ts`. Reused by SLA, job badges, `quiet-hours-chip`, pet proactive.
- **Build-options pipeline**: `lib/claude/build-options.ts:resolveSendOptions` is where A2UI, brief mode, active goal, computer-use tools, twin runtime, and per-channel capability prompts converge.
- **Per-run capability grants** (ADR-0198): a feature that launches an agent customises that run with `AgentCapabilityGrantV1` (`packages/agent-config-types/src/agent-capability-grant.ts`) passed as `BuildOptionsContext.capabilityGrants` / `ExecuteAgentConfig.capabilityGrants`. Never edit the `SendOptions` a resolver returned to add or remove tools, skills, MCP servers or permission: that skips the filter, Restricted Mode, the ceiling and the finalizer. A module that customises every run it applies to contributes grants through its manifest (`capabilityContributions: { load }`, a file exporting `contributions` of `{ id, failure, produce }`; ADR-0198 amendment) instead of adding a branch to `build-options.ts`: `"skip"` contributions may only add, anything that narrows is `"refuse-turn"`, and none may set `model`, `provider`, `effort`, `maxTurns` or `permissionProfile`.
- **Agent variants** (ADR-0199): several configurations of one agent are variants (`Character.variant`, `packages/agent-config-types/src/agent-variant.ts`) that follow a base, not duplicates. Runtime code reads agents through `resolveCharacterById` / `listCharactersByIds` (which apply the overlay), never raw `getCharacter`.
- **A2UI ⇄ IM bridge**: `lib/connectors/a2ui-bridge/*` projects assistant surfaces into platform rich content and routes callbacks via `ConnectorBus.dispatchConnectorCallback`. Shared mapper `lib/connectors/adapters/_shared/a2ui-mapper.ts`.
- **Typed topics** (ADR-0250 §14): a module that other modules need to read state from publishes it as a retained topic, never as an import of its internals. Declare it in `types/<id>/**` by merging into `TopicMap` (`lib/runtime/topics.ts`), publish from a module effect with `publishTopic` / `clearTopic`, read with `useTopic` (`hooks/use-topic.ts`) or `readTopic` / `subscribeTopic`. First topic: `pet.status` (`types/pet/events.ts`), read by the tray and the glance.
- **Node-only modules**: browser-unsafe deps and Node built-ins are stubbed to `lib/browser-stubs/empty.js` through `NODE_ONLY_MODULES` in `next.config.ts`. Add new ones there or the mobile bundle breaks.

## Testing Standards

- **Co-located** `xxx.test.ts(x)` next to source. No `__tests__/` or `tests/` directories. Pre-existing gaps live in `scripts/gates/colocated-test-baseline.json` and that list may only shrink.
- **Rust**: in-file `#[cfg(test)] mod tests`. Integration tests in `src-tauri/tests/` allowed.
- **Excluded**: `components/ui/`, `components/ai-elements/`.
- **Coverage is opt-in**: `pnpm test:coverage` and any ≥90% target only run when the user explicitly requests a coverage check — it is not a default completion gate.
- Which runner owns what is in [`CI_CD.md`](./docs/development/CI_CD.md).

## Commit Hooks

Husky via the root `prepare` script. `pre-commit` → `lint-staged` (eslint --fix + prettier) and `lint:i18n:staged`. `commit-msg` → commitlint (Conventional Commits). Never `--no-verify`. A failed hook means fix the root cause and make a **new** commit.

## Critical Notes

- **pnpm only**, from repo root.
- **Never remove `output: "export"`** from `next.config.ts`. Tauri and Capacitor consume `out/`. `docs/next.config.ts` is a separate static export.
- **Dexie schema is one current store set over a frozen baseline**: `lib/db/schema.ts` declares the whole store set as `CURRENT_SCHEMA` at `CURRENT_SCHEMA_VERSION` (read the constant; this file does not track the number), on top of the frozen `SCHEMA_V240` and the v240–v242 backfill steps. Don't add `upgrade()` backfills without asking. Follow the `dexie-migration` skill. To change it: edit `CURRENT_SCHEMA`, **bump the version** (an un-bumped edit is silently ignored on existing databases), add the table to `CORE_TABLE_NAMES` in `lib/data-governance/table-catalog.ts`, run `pnpm db:governance:write`. Drop a table by setting it to `null`, never by deleting the key. A mismatched `storageLayout` marker is refused at boot and routed to an explicit reset. Local data is not migrated.
- **Native vector store**: sqlite-vec at `<app_data>/cognia/vectors.sqlite`. Web mode forces cloud.
- **Rust toolchain**: pinned in `rust-toolchain.toml`.
- **Sidecar code is strict TypeScript that Node runs unbuilt** (ADR-0197): new sidecar modules go in `sidecar/src/<layer>/` as `.ts` (erasable syntax only, relative imports spell `.ts`, `import type` for types), never as new `.mjs` outside a launcher. `pnpm sidecar:typecheck` and `pnpm audit:sidecar-architecture` must pass. A `link:` package the sidecar imports at runtime needs a `node` export condition pointing at compiled `dist/`: the bundle copies it under `node_modules`, where Node refuses to strip types.
- **Every subsystem has one owner** (ADR-0250 §14): a new top-level directory under `lib/`, `components/`, `hooks/`, `stores/`, `types/` or `app/` needs a `lib/<id>/module.ts` written with `defineHostModule` from `@/lib/modules/define` (a plural directory the subsystem classifier aliases holds its subsystem's manifest: `lib/artifacts/module.ts` is `artifact`) (UI parts in `components/<id>/module.ui.ts` with `defineUiModule`), or a row in `scripts/gates/module-ownership.json`. That table and `scripts/gates/modules-baseline.json` only shrink: a new row, a new cycle member, a new module or a new vendor branch in a framework directory needs a record under `scripts/gates/baseline-exceptions/`. `pnpm audit:modules` checks it.
  - **Dependency direction blocks (G2).** Foundation imports nothing above it, the kernel no module or shell, a module no shell. A shell's contribution kit (settings section parts, search provider helpers) is listed as its `api` in the ownership table and may be imported.
  - **Modules talk through `api` files (G3) and declare what they use (G4).** An import into or out of a module with a manifest must reach a file the target lists as `api` (its manifest's, or its row's in the ownership table), or `types/**`; an `api` file is never a barrel. The manifest's `dependsOn` names exactly the modules its files import, and any `tables` or `settings.keys` it declares must exist, be touched by its files and be claimed once. A claimed table is its claimant's: the data catalog's `owner` follows the claim, another module reading it directly (`db.<t>`, `getDb().<t>`, `.table("<t>")`) fails G4 unless baselined in `tableAccess`, and a `lib/db/` file only one manifest module imports must be in that module's `owns`. Needing another module's internal file means listing it as that module's `api`, not baselining the import.
  - **A module's settings section, search provider, slash command or navigation destination goes in its manifest** (`settingsSections`, `searchProviders`, `slashCommands`, `nav`), never in `settings-nav-config.ts`, `settings-shell.tsx`, `lib/global-search/providers/index.ts`, `lib/slash-commands/builtin.ts`, `SIDEBAR_NAV_META`, the rail/phone icon tables, `GO_MENU_LAYOUT` or the full-viewport list. Shells read destinations from `lib/shell/nav-catalog.ts` and look labels up as full keys. The registries those shells read are generated by `scripts/build/gen-module-registry.mjs` and gitignored; every dev, build, Jest and typecheck entry point regenerates them.
  - **A module's runtime goes in its manifest's `runtimes`**, never in a new provider initializer or a `lib/headless/runtimes/` registration: one adapter per host as a module specifier (the brain's as `{ module, hosts }`, its `start` being `HeadlessRuntime.start`), a reason in `absent` for each host without one, and `boot` for the deferred group it waits for. The generator writes each host's lazy imports into `lib/modules/generated/{brain,desktop,mobile}.ts`; the brain roster (`lib/headless/runtimes/modules.ts`) and `ModuleRuntimeHost` start them.
  - **An interchangeable capability is a port** (`lib/modules/ports.ts`): the kernel declares the contract in `types/modules/ports/<id>.ts` (merging into `PortMap`), one module `provides` it (`{ port, load }`, the file exporting `port`), and users call `loadPort` / `readPort` / `usePort` (`hooks/modules/use-port.ts`) instead of importing the implementation. A manifest module names the ports it asks for in `requires` (`"x?"` when it copes without); `null` means no active provider. A capability with several interchangeable providers at once is a collection port: its contract merges into `PortCollectionMap`, every providing module adds a member, and its framework reads them with `loadPortCollection` / `readPortCollection`. Ports so far: `speech`, `ocr`, `conversation-file-links`; collection ports: `docs-provider`.
  - **A module's settings keys are claimed in its manifest** (`settings: { keys, section? }`, flat `AppSettings` keys) and read and written through one view, `defineSettingsView(module.settings.keys)` from `stores/settings/view.ts`, exposed in the module's `api` (`lib/speech/settings.ts`, `lib/pet/settings.ts`, `lib/eval/settings.ts`). Never add a module-only setter to `SettingsState` or a module's keys to `SECTION_OWNED_KEYS` by hand: the section's entry is derived from the manifest. A view writes only its own keys. Reading a key another module claims through the settings store is a `settingsAccess` baseline entry that only shrinks; read it through the owner's `api` instead.
  - **A module's code-owned prompts reach the Prompt Center through its manifest** (`prompts: () => import("./prompts")`, a file exporting `prompts`), never as an import in `lib/prompts/catalog.ts`: the generated `lib/modules/generated/prompts.ts` lists them lazily, and anything that reads the catalog awaits `loadPromptCatalog()` first. A manifest module that calls `definePrompt` must declare `prompts` (G4).
  - **A module's in-process agent tools go in its manifest's `tools`** (ADR-0250 §14 amendment), never as a new `lib/claude/*-builtin-tools.ts` family, a `lib/claude/permissions/*-tool-rules.ts` tier, a branch in `build-options.ts` or `plugin-tool-ipc.ts`, or a hand-added name in the outbound, probe or live-voice lists: `tools.declare` gives each tool's `consent` (`allow` / `ask` / `per-call`, or `default` for no rule) and `effect` (`read` / `write` / `outbound`) as data, and `tools.load` names a file exporting `toolFamily` (`surface(ctx)` → the tools this run offers, or `null`; `run(name, args, call)`). The kernel derives the ruleset, `requiresApproval` and every name list from the declaration (`lib/modules/tool-declarations.ts`, `lib/claude/tool-contributions.ts`); a per-call tool must also be on the sidecar's `PER_CALL_PLUGIN_TOOL_NAMES`.
  - **A module's system-prompt text goes in its manifest's `context`** (ADR-0250 §14 `context` amendment), never as a new branch in `build-options.ts` that pushes onto the dynamic tail or a `systemPrompt` slot, a new `SendOptions.*Context` field, or a per-session registry the module fills while a send resolves: `context.load` names a file exporting `contributions` (`{ id, cache: "turn" | "session", slot?, pii?, deadlineMs?, after?, produce(ctx) }`; `after` waits for another contribution of the same module, one level, and reads its `handoff` as `ctx.prior`; `ctx.kernelRetrieval.identityTexts` holds what the `identity` section retrieved; that slot, one module at most, replaces the base system prompt and runs first). The kernel places each section (tail or one of the closed `slot`s), PII-gates it, files its `sources` under `SendOptions.contextSources["<module>.<id>"]` (typed by merging into `ContextSourcesMap`, read back with `contextSourcesOf` from `lib/claude/context-sources.ts`) and keeps its `sessionState` for the module's own tools (`ToolCallContext.sessionState`, and `ToolSurfaceContext.sessionState` to decide what to offer; teardown drops it with `forgetContextSessionState`) (`lib/claude/context-contributions.ts`, `lib/claude/context-session-state.ts`). Example: the `knowledge-base` module's reader scope and retrieval (`lib/knowledge-base/context.ts`) with its `knowledge_*` tools. Caller-built host deps arrive by name in `ctx.hostDeps` (`ContextHostDepsMap`).
  - **A module's slot contribution or side effect goes in its UI manifest** (`slots` keyed by a canonical extension point, `effects`), never in a hand-mounted initializer or a direct import into the slot's host: `PluginExtensionSlot` draws module entries ahead of plugins and `ModuleEffectsHost` mounts effects, each behind a `ModuleBoundary`. A settings section that needs a paired host's operation off the desktop names it in `hostOperation` (the pet's `pet_get`) instead of a `profiles` restriction.
- **New Rust code goes in a crate, not `src-tauri/src`** (ADR-0196): put logic in the lowest-layer crate under `crates/` that can own it (layers in `scripts/gates/rust-architecture.json`). `src-tauri/src` only assembles the desktop app (`lib.rs`, `startup/`, window/tray/webview code, `AppHandle` adapters); a new top-level module there fails `pnpm audit:rust-architecture`. A library crate's `#[tauri::command]` shells and `AppHandle` adapters sit behind its `tauri-host` feature, which only `src-tauri` enables.
