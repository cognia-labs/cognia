The following audit obligations follow from the verified contracts. These are inferences to investigate in Cognia.

- Define task eligibility separately from whether an engine can accept a call. Recheck after queueing, before retries and while a run is active.
- Account for concurrency, retry attempts, elapsed time and stalled progress at the durable work or PR owner, so a replacement run does not reset every budget.
- Distinguish an agent claiming checks passed from a deterministic checker producing a result for the delivered commit and environment.
- Bind review policy to an approved revision outside the change under review. Keep proposed changes separate from the privileged write that publishes them.
- Preserve PR identity and branch ownership during feedback repair, including stacked PRs and multiple-repository work.
- Require sufficient diagnostic context at intake and preserve its source through triage, execution, review and customer updates.
- Treat code merge, release inclusion, deployment and user-observed resolution as independently evidenced milestones.

This check did not inspect the remaining product examples in the supplied survey or benchmark any product. It does not establish production security or reliability of the referenced implementations.
