# Cognia Code Mode 现状与可行性评估

日期 2026-11-19。以本地 `dev` 的 `eeb1610a85` 和当前工作树为准。

## 结论

**Cognia 已经实现原生、只读的 Code Mode。可以从现有实现恢复桌面实验功能，当前主发送路径还无法兑现界面选择。** ADR-0117 已定义 `native`、`code`、`both`，两套内置 Agent sidecar 都有 `run_code`、类型声明生成、独立执行进程和逐次工具授权。应先修通执行 Host 的能力传递，再验证停止、输出限额和嵌套调用观测。现阶段可推进只读原型，跨 MCP、写入和默认开放仍缺发布条件。 [ADR-0117](../content/docs/en/adr/0117-composed-agent-modes-and-creator.md#L82) · [工具面实现](../../sidecar/src/tools/middleware/presentation.ts#L39)

Code Mode 关心的是**一次模型生成的程序可以消费工具结果并继续调用其他工具**。这能缩减串联步骤间的模型请求，也能让脚本主动筛选输出。工具定义延迟加载、同时发出多次互不依赖的调用、保存工作流和运行语言代码各有自己的作用。 [外部机制与基准核验](2026-11-19-code-mode-external-references.md)

**本机批量执行稳定性也需要验收。** Supervisor 每 25 ms 同步调用 `ps` 采样进程组 RSS。通过仅计时、保留实际采样的探针连续运行 5 个 `return 42`，在 1.5 秒的测试预算下 2 次成功、3 次超时。每次超时在同步采样中累计停留约 1.07–1.13 秒。这确认了当前实现的事件循环开销，尚未确定批量延迟增长的完整原因，也不能直接外推到发布版。 [采样实现](../../sidecar/src/tools/builtin/run-code/supervisor.ts#L386)

## 推荐推进顺序

1. **打通桌面 `both` 的只读试点。** 延用 ADR-0117 的会话字段与 `run_code`。由实际执行 Host 报告专用 launcher 能力，UI、发送和 Host 最终注册使用同一能力语义。首个验收执行“搜索 → 按搜索结果读取 → 只返回摘要”。使用现有模型夹具，验证最终发送 spec、实际模型工具表、动态依赖、禁用工具和缺 launcher 时的结果。首次灰度以 macOS 打包版为准，Linux 单独验收。保留现有 `native` 默认。
2. **补齐 Stop、审计和输出验收。** 在同一次调用持有父调用 ID，并在每个实际调用检查会话/Agent 作用域和当前授权。将脚本进程、IPC、等待审批及在途调用纳入终止流程。限制单条 IPC、日志累计及单会话并发。用 `run_code`/子调用 ID 记录工具名、审批和终态、耗时、字节数和限额事件。验收 Stop 后无新调用、所有等待有终态、无遗留子进程、输出复核生效、Host 能撤回 `run_code`。
3. **用等任务对照确定收益，再扩到外部工具。** 用同模型、快照、权限和正确性判定比较直接调用、直接调用+Tool Search、`both`。覆盖简单读取、依赖链读取和大结果聚合，记录正确率、模型请求数、实际工具次数、费用及 cache token、p50/p95、拒绝与取消。可用仓库已有 keyless replay 做确定性回归，再单测真实 provider 的收益。二阶段先选一个用户授权、Host 明确审核的只读 MCP 连接。使用稳定的 server/tool 标识和已有 broker，验证逐次授权、结果契约及撤回。写入工具需要独立的作用域、审批、取消与重试回执设计。

Claude Code 原生实验仅适用于其受支持的交互式终端，Agent SDK 不提供同一模式。Anthropic API Programmatic Tool Calling 和 Cloudflare 的 SDK 可参考目录分发、逐次调用和持久审计。原附文引用的 96 次第三方实验中，MCP 聚合累计处理 tokens 的降幅为 62%–77%，文件类表现随模型变化。Cognia 的 MCP 尚未接进 `run_code`，因此需要自己的效果对照。 [外部来源与原始基准](2026-11-19-code-mode-external-references.md)

Vercel 的 `@ai-sdk/code-mode` 是额外依赖，当前 sidecar 没有安装。它有与当前 `ai@7.0.163` 匹配的版本，也有独立审批续跑 API。替换现有执行器仍需验证 Cognia 的 OS 隔离、工具目录、审批/撤回、内容安全和轨道兼容。Anthropic/OpenAI 的 provider 托管执行也各有适用入口，不能覆盖 Cognia 当前的跨 provider 本地执行目标。当前只读试点保留原生 `run_code`，将上述机制作为后续执行器比较项。 [当前依赖](../../sidecar/package.json#L17) · [适配器与 provider 参考](2026-11-19-code-mode-external-references.md)

## 本轮验证

- 源码探针运行真实 `resolveTurnCompositionSafely` 和 `resolveTurnComposition`。正向能力样本输出 `explicitProbe: [native, code, both]`，安全发送包装输出 `safeSend: native` 并给出 `presentation-unavailable`，显式把能力传给底层 resolver 后输出 `code`。探针在 Node 运行，发送路径的归因来自 UI 到 sidecar 的调用链。
- Sidecar 的六个文件用 `scripts/test/run-sidecar-tests.mjs` 运行，**121 通过**。覆盖 `run_code`、SDK 声明、资格表、工具面、中间件及两种运行时的嵌套审批。Jest 的会话解析、探针与 UI hook 五个套件 **42 通过**。
- 筛选 supervisor 现有测试，首轮 **19 通过、2 失败**，同样选择重跑 **18 通过、3 失败**。超大结果与调用次数上限用例曾先触发墙钟超时，console 用例未在 30 秒内返回成功。仅重跑这三个失败用例时 **3 通过**，其中 console 仍耗时约 26.4 秒。批量子进程启动延迟和结果稳定性仍需在发布环境测量。
- 这些测试和探针使用受控夹具，部分进程测试用 `/usr/bin/env` 验证 launcher 与 IPC 接线。2026-11-08 记录了实际 macOS sandbox-exec 子进程的历史结果。本轮无打包版、Linux bwrap、配对设备、真实模型、整仓构建或性能对照结果。本次产物为研究记录。 [当前 supervisor 夹具](../../sidecar/src/tools/builtin/run-code/supervisor.test.ts#L20) · [历史 macOS 证据](../evidence/2026-11-08-builtin-agent-tool-support-audit.md#L192)
