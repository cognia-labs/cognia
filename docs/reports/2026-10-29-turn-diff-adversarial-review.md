# Turn diff adversarial review and support matrix

Date: 2026-10-29 (Asia/Shanghai)

Source scope: current dirty Cognia checkout at HEAD `bf8af10d45`. This is a follow-up to [the implementation inventory](2026-10-29-turn-diff-implementation-research.md). A separate review artifact preserves the distinction between the initial inventory and independently challenged conclusions. No production source or co-located tests were changed; reproducers live under ignored `.cache/turn-diff-audit/` and use temporary workspaces.

## Verdict and review contract

Turn diff is **not uniformly supported across agents or environments**, and the shared ledger/review path currently has correctness defects. The most serious reproduced issue changes patch payload bytes and then reports a successful partial application. Other reproduced issues lose changes, bind a run to another turn's message, show another selection's stale body, and include an undisplayed user upload in whole-patch Undo.

The claims tested were: a historical turn shows all and only its recorded changes; the displayed root/run matches the body and Undo target; patch construction preserves bytes; and the capture Host observes the executor's actual working directory. These matter because a misleading review can authorize an incorrect mutation.

Three fresh-context, read-only reviewers independently inspected (1) capture/parser/UI/Undo correctness, (2) runtime adapters and entry points, and (3) environments/transports/persistence. They received source artifacts and this contract, without the previous inventory's conclusions. Findings were reconciled against owning source and focused behavioral checks. This was one review cycle, not an implementation/repair cycle. The user chose repository-local independent review and declined an additional external CLI review.

## Actionable findings

### A1 — P1: Path normalization corrupts patch payload and partial application

**Native public-service reproduction.** `unified_diff` replaces `a/old/` and `b/new/` across the entire patch string, including added/deleted/context lines, rather than only file headers ([ledger.rs:728](../../crates/cognia-task-workspace/src/ledger.rs#L728)). Selected-hunk application reads those altered blobs and calls `git apply` ([ledger.rs:774](../../crates/cognia-task-workspace/src/ledger.rs#L774)).

The real `TaskWorkspaceService` captured execution content `unchanged\na/old/resource\nb/new/value\n`. `read_patch_diff` returned additions `+a/resource` and `+b/value`; applying the selected hunk returned `Applied` and installed `unchanged\na/resource\nb/value\n`. This is actual incorrect output, not merely a display discrepancy. Whole-file application uses a separate blob path; this reproduction specifically establishes the partial-hunk path.

Required correction: rewrite only structural headers and prove forward/inverse patches preserve arbitrary payload bytes with both display and partial-apply tests.

### A2 — P1: Same-file later hunks disappear from desktop Review

**Reproduced through the actual scope loader.** Each stored hunk contains its own file preamble ([ledger.rs:731](../../crates/cognia-task-workspace/src/ledger.rs#L731)); `read_patch_diff` concatenates them ([service.rs:4811](../../crates/cognia-task-workspace/src/service.rs#L4811)). The parser returns separate same-path file records, and the loader selects only the first with `.find()` ([scope.ts:362](../../lib/review/scope.ts#L362)).

Two separated changes in one file produced two parser records but only one displayed hunk. The patch list can contain every hunk while View shows only the first; whole-patch Undo can affect more than was displayed. The previous inventory's F1 is confirmed independently.

### A3 — P1: Async settlement binds an old run to a newer assistant message

**Reproduced with actual tracker code in both Jest and an independent in-memory check.** Settlement awaits Host settlement and the legacy read before resolving the closing assistant message from the then-current transcript ([turn-tracker.ts:199](../../lib/code-adoption/turn-tracker.ts#L199), [message lookup:217](../../lib/code-adoption/turn-tracker.ts#L217)). It does not capture the ending message identity at the status edge or filter the lookup by the ending run.

Delaying settlement/legacy completion, appending the next user and assistant messages, and releasing the delay persists run 1's `first.ts` patch with `assistantMessageId: a2` instead of `a1`. The old card can disappear from its message and appear under another turn. The independent native-free reproducer delays the legacy read after Task Workspace settlement has completed, so it does not require a second managed run to acquire a still-held working copy.

Required correction: retain a run-owned closing-message identity before asynchronous reconciliation, including no-assistant and background cases.

### A4 — P1: Whole-patch Undo includes a user file omitted from the card

**Native upload/apply/undo reproduction.** Resource upload is explicitly attributed to `ContributionOrigin::User` ([service.rs:5092](../../crates/cognia-task-workspace/src/service.rs#L5092)). The patch includes every source change ([service.rs:4153](../../crates/cognia-task-workspace/src/service.rs#L4153)), while the chat projection filters to agent-origin changes ([turn-tracker.ts:118](../../lib/code-adoption/turn-tracker.ts#L118)). The card invokes whole-run Undo ([turn-changes-card.tsx:123](../../components/chat/turn-changes-card.tsx#L123)).

The real service captured agent-only projection `[agent.txt]` but patch files `[agent.txt, user.txt]`. After full apply, `undo_patch_set` returned `Reverted` and removed uploaded `user.txt`. The UI count/list therefore does not reliably describe the mutation boundary. This finding does not claim that the engine overwrites unrelated post-apply edits; it establishes that an in-run user contribution can be included in the recorded operation despite being omitted from its card.

### A5 — P1: Multi-root chat summaries target only the primary run

**Source-confirmed structural mismatch; native backend cascade tests pass.** Bundle activation retains the primary run in `activeBySession` ([client.ts:232](../../lib/task-workspace/client.ts#L232)); settlement flattens all roots' resources ([client.ts:465](../../lib/task-workspace/client.ts#L465)). The adoption row drops each resource's root/run identity, retaining only relative paths and the primary `taskWorkspaceRunId` ([turn-tracker.ts:118](../../lib/code-adoption/turn-tracker.ts#L118), [run binding:206](../../lib/code-adoption/turn-tracker.ts#L206)). The card's View and Undo then target that one run ([card:79](../../components/chat/turn-changes-card.tsx#L79), [view:109](../../components/chat/turn-changes-card.tsx#L109)).

Additional-root files can be counted without appearing in the selected patch, and equal relative paths from different roots collide. The backend has bundle-wide operations; the single-run chat projection does not preserve that boundary. No real multi-root UI Undo was executed.

### A6 — P2: Switching root/run can show the previous selection's body

**Reproduced with the actual React component.** SnapshotReview keys listing state by root plus selection, but keys diff state only by file path ([snapshot-review.tsx:70](../../components/artifacts/workspace-mode/snapshot-review.tsx#L70), [state:106](../../components/artifacts/workspace-mode/snapshot-review.tsx#L106), [display:297](../../components/artifacts/workspace-mode/snapshot-review.tsx#L297)).

After A's body loads, switching to B with the same `src/a.ts` and delaying B's body leaves A's content visible after B's file list is ready. Cleanup prevents an old request from completing late; it does not invalidate a body already stored. Full root/run/selection identity is needed on the body state.

### A7 — P1: A chmod-only text change prevents settlement

**Native public-service reproduction on macOS.** Reconciliation treats a mode change with identical bytes as `Modified` ([service.rs:6856](../../crates/cognia-task-workspace/src/service.rs#L6856)). `build_patch_set` then requests textual hunks ([ledger.rs:52](../../crates/cognia-task-workspace/src/ledger.rs#L52)), but both scratch files have identical bytes; splitting the empty diff throws `text diff did not contain a hunk` ([ledger.rs:736](../../crates/cognia-task-workspace/src/ledger.rs#L736)).

Changing only file permissions produced that exact `settle_run` error and `get_patch_set = None`. Passing apply/undo tests for creates/deletes/renames/binaries/symlinks do not cover this mode-only case. An empty text patch must be valid metadata-only change data rather than aborting the run's reconciliation.

### A8 — P2: Valid hunk content can be mistaken for file headers

**Actual parser reproduction and failing behavioral probe.** The parser recognizes a `--- ` / `+++ ` pair as a file boundary before respecting the active hunk's remaining line counts ([unified-patch.ts:197](../../lib/git/unified-patch.ts#L197)). A valid one-line change from `-- old body` to `++ new body` therefore yields `[]` instead of one file with one hunk. This is independent of A2's repeated-preamble format problem.

### A9 — P2: Missing/pruned patch is silently presented as an empty scope

**Failing behavioral probe.** A `null` `getTaskPatchSet` result becomes `patch?.files ?? []`, without an unavailable reason ([scope.ts:222](../../lib/review/scope.ts#L222)). Listing returns `files: [], unavailable: []`; SnapshotReview presents `snapshot.empty` ([snapshot-review.tsx:251](../../components/artifacts/workspace-mode/snapshot-review.tsx#L251)). Expired, missing, wrong-Host and genuinely empty history need distinct states.

### A10 — P2: Historical turn reads follow the currently selected Host

**Source-confirmed; no cross-Host behavioral reproduction.** Adoption rows retain run/root but no origin Host ([types.ts:39](../../lib/code-adoption/types.ts#L39)). Read wrappers pass only run/path ([client.ts:1069](../../lib/task-workspace/client.ts#L1069)) through the global transport ([user-action.ts:319](../../lib/task-workspace/user-action.ts#L319)); execution commands route to current `activeRemote` ([transport-routing.ts:176](../../lib/tauri/transport-routing.ts#L176)). No run-owner lookup or pinned originating transport was found in this path.

After changing Host, the local historical picker/card requests its old run from the new Host. Normally this yields null/unknown-run, including A9's misleading empty state. Same-ID collisions were not exercised and are not required to establish the availability defect. Mutation operations also need an explicit owning execution target and its own lease.

### A11 — P1: Legacy OpenCode does not consume the managed turn cwd

**Source-confirmed execution/capture mismatch; no live OpenCode run.** V1 `createSession` sends title/parent metadata but not `SessionCreateOptions.cwd` ([client.ts:821](../../packages/agent-opencode/src/client.ts#L821)); fork/resume similarly omit requested cwd ([fork:878](../../packages/agent-opencode/src/client.ts#L878), [resume:906](../../packages/agent-opencode/src/client.ts#L906)). Auto-spawn uses configuration-level `process.cwd` ([spawn:590](../../packages/agent-opencode/src/client.ts#L590)).

The common chat path can successfully snapshot its managed alias even when this executor is writing somewhere else. This is an isolation/capture contract break, not evidence that an empty captured patch means no edit occurred. V2 consumes `location.directory` and validates resume-directory agreement ([v2-client.ts:677](../../packages/agent-opencode/src/v2-client.ts#L677), [resume:783](../../packages/agent-opencode/src/v2-client.ts#L783)).

### A12 — P1: Host-owned external Chat has no identified capture owner

**Source-confirmed lifecycle gap in this entry point; no live remote-agent run.** The renderer explicitly excludes `hostOwnedExternalTurn` from working-copy acquisition because the RPC carries no cwd/workspace envelope ([controller:3725](../../hooks/chat/use-claude-chat-controller.ts#L3725)). The remote run service optionally resolves a headless working directory and directly calls `manager.execute`, without Task Workspace begin/settle ([remote-run-service.ts:888](../../lib/ai/agent/external/runtimes/remote/remote-run-service.ts#L888)).

No alternative capture owner was found along this path. The separate generic Agent Execution Service has conditional tracking, but this call goes directly to the external manager, so its existence cannot establish coverage here. Starting an agent on a paired Host and reading an existing Host ledger are separate capabilities.

## Other retained limitations and corrected interpretations

- **Created/deleted/renamed textual bodies:** those patch entries retain hashes/modes without text hunks. A native created-file check captured one file and returned an empty diff string. Binary/symlink textual reads are refused. This limits presentation; native apply/undo/reopen tests for those resource kinds pass. [Builder](../../crates/cognia-task-workspace/src/ledger.rs#L52), [reader](../../crates/cognia-task-workspace/src/service.rs#L4787).
- **Local fallback is not historical patch support:** explicit Local bypasses managed acquisition. Legacy fingerprint tracking is Tauri-only, Git-only and best effort; it can show a card that opens the current uncommitted diff and offers no exact patch Undo. It determines changed paths by fingerprints but obtains counts from current Git index/worktree diffs, so it does not establish precise subtraction of pre-turn dirt on a path edited again. [Gate](../../hooks/chat/use-claude-chat-controller.ts#L4067), [legacy client](../../lib/code-adoption/client.ts#L43), [attribution](../../crates/cognia-git/src/code_adoption/attribution.rs#L13), [card fallback](../../components/chat/turn-changes-card.tsx#L108).
- **Native protocol diff is separate:** Codex `turn/diff/updated` only changes in-memory metadata; no product consumer was found. OpenCode V1's native `getSessionDiff` likewise has no identified product caller. Neither proves a shared retained turn-diff/Undo workflow. [Codex](../../packages/agent-codex/src/app-server-client.ts#L2604), [OpenCode](../../packages/agent-opencode/src/client.ts#L1513).
- **Codex file hints use mismatched session identities:** the adapter sends its native session ID; the sink indexes `activeBySession` with it, while the manager separately stores `cogniaSessionId`. This can drop causal hints. It does not by itself establish lost authoritative snapshots. [Callback](../../packages/agent-codex/src/app-server-client.ts#L2950), [sink](../../lib/task-workspace/tool-evidence.ts#L40), [mapping](../../lib/ai/agent/external/manager.ts#L3850).
- **Host bodies and local picker have separate retention:** `codeAdoptionTurns` is local-only and capped at 10,000 rows. Host SQLite/blobs have independent policy, defaulting to 30 days with pin/pending/conflict protections. Another device's transcript or Host run does not automatically produce local turn-picker rows, and offline body availability is not durable. [Local persistence](../../lib/code-adoption/persist.ts#L1), [Host configuration](../../crates/cognia-task-workspace/src/service.rs#L48), [prune](../../crates/cognia-task-workspace/src/service.rs#L4491).
