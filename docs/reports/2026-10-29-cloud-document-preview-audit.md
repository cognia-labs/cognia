# Cloud-document previews in the right-side dock

Date: 2026-10-29, Asia/Shanghai. Scope: current working-tree source and existing focused tests. This is a research result, not a preview implementation or live-provider acceptance record. The checkout contains extensive concurrent changes; observations describe the inspected source, not a released build.

## Conclusion

**Partially supported.** Feishu and Google documents can already enter chat as fetched text attachments. Ordinary Markdown web links can already open in the right-side dock's browser page tabs. A unified cloud-document preview that carries provider identity, content, provenance and refresh state across attachments, citations and tool results is not currently wired into that dock.

The user's expected location is consistent with the current dock architecture: it already hosts artifacts, browser pages and workspace panels. A new independent right sidebar is unnecessary.

## What “preview” can promise

1. **Original webpage:** The right dock already has this route. Desktop supports a native embedded WebView and managed local Chromium, with explicit alternatives; a standalone browser falls back to an iframe when no remote browser is available. Loading private content depends on the chosen browser's authenticated session and the provider's behavior. An API OAuth connection alone does not prove that the browser page is logged in. [Browser routing](../../lib/browser/backend-availability.ts), [page renderer](../../components/artifacts/chat-dock-panels.tsx), [web fallback](../../components/browser/browser-web-fallback.tsx).
2. **Fetched content snapshot:** Existing `DocsProvider.fetch` returns text/Markdown/CSV, never HTML or a native embedded document. This can support a readable dock preview, but it does not preserve all original layout, images, comments, formulas or collaboration. The current limits include 200,000 text characters, 10 sheet tabs, 500 rows × 50 columns per tab, and 5 Bitable tables × 200 records. A snapshot needs an explicit completeness indicator. [Content contract](../../lib/docs-providers/types.ts), [limits](../../lib/docs-providers/limits.ts).
3. **Provider-native embedded document:** This is additional integration work. Google documents published embedding; Feishu documents an authenticated Cloud Docs web component. Neither establishes universal ordinary-link iframe support. See the [provider research](2026-10-29-cloud-document-provider-preview-research.md).

Google officially supports Slides text/PDF export. The local comment that Slides has no useful text read is therefore not a valid platform limitation; the accurate statement is that this provider has not implemented Slides. [Local implementation](../../lib/docs-providers/providers/google/index.ts), [official export formats](https://developers.google.com/workspace/drive/api/guides/ref-export-formats).

## Recommended next increment

Use the existing right dock as the destination, with two explicit actions: **Preview content** and **Open original**.

1. Route cloud-document attachment/citation/result actions through the existing dock. Reuse `requestBrowserUrl` / `openDockPage` for Open original. Make relevant Sources links consistent. A user click should reveal the chosen tab; merely streaming a document URL should not repeatedly steal focus.
2. Add a read-only content preview to the existing dock resources/panels. Reuse the existing document/file renderers where suitable, including the `providedText` route in [FilePreviewSurface](../../components/file-viewer/file-preview-surface.tsx). Keep human-readable fetched content distinct from the wrapped/redacted model view. Grids can initially retain their declared CSV representation rather than implying a full spreadsheet editor.
3. Carry provider id, resource id/type, canonical URL, bound account/authorization generation, fetch time and completeness through the preview request. These are proposed additions, not fields the current generic citation already retains. Reuse provider authentication/cancellation and attachment ownership; do not create a second credential store or duplicate the document body across unrelated stores. Refresh must preserve the selected identity and reject stale results after account/session changes.
4. Render loading, empty, permission-denied, expired authorization, unavailable host and truncated/partial states. Reader-unavailable clients should offer the original-page option and explain the content-preview limitation.
5. Evaluate Feishu's web component only when native layout/comments/collaboration are required. Google Publish to web embeds should be limited to sources deliberately published by their owner; previewing must not publish a document or broaden sharing.

This recommendation follows [ADR-0134](../content/docs/en/adr/0134-remote-document-providers.md), which separates cloud reads from messaging connectors, and [ADR-0214](../content/docs/en/adr/0214-the-chat-dock-is-a-tabbed-browser-that-remembers-each-task.md), which places browser pages beside artifacts in the conversation's dock. No new `ArtifactType` is required just to open an original URL. The final snapshot representation should be chosen against existing dock/file-preview ownership before expanding the public plugin contract.

## Verification and limits

The repository Jest entry point ran successfully against installed dependencies:

```sh
rtk proxy pnpm --config.verify-deps-before-run=false test --runInBand --runTestsByPath lib/docs-providers/providers/lark/index.test.ts lib/docs-providers/providers/google/index.test.ts lib/docs-providers/reach.test.ts hooks/chat/use-remote-doc-staging.test.tsx components/chat/composer/attachment-preview-dialog.test.tsx components/shared/external-link.test.tsx lib/browser/open-url-request.test.ts lib/browser/backend-availability.test.ts lib/artifacts/dock-pages.test.ts
```

Result: **9 suites passed; 206 tests passed; exit 0.** An existing asynchronous `FilePartPreview` React `act` warning was emitted. Staging error fixtures also emit expected warning logs. No coverage run was requested or performed.

An initial ordinary `pnpm test` triggered pnpm's automatic dependency synchronization and failed in postinstall before Jest started: `@cognia/agent-config-types/plugin-interception resolves to .../src/plugin-interception.ts`; the sidecar checker requires compiled JS under a Node export condition. Disabling only that automatic dependency synchronization allowed the actual repository test entry point to run; no test assertion or quality gate was disabled. A research-agent formatting invocation encountered the same preparation failure before using the installed formatter directly.

CodeGraph has no index in this checkout, so navigation used literal search and owning-source reads. No runtime preview feature was changed. No real Feishu/Google account, private document, login flow, native SDK, rendered browser/Tauri/mobile acceptance, full build/typecheck/lint or production static export was exercised. The test result establishes fixture contracts, not live private-document preview support.

Before implementing, acceptance should cover: cloud picks and links opening in the correct dock/session; repeat-open deduplication; original versus snapshot/model-view distinction; actual permitted and denied Feishu/Google documents; account switch/revoke/cancellation during refresh; truncation; unsupported hosts; and independent login/cookie behavior in the selected browser engines. A browser/Tauri visual check is required for that implementation.
