## 第二轮复核

同日复核了同一应用和服务版本。三位独立审查者分别挑战删除与同步、密码与恢复、登录与入口的实际可达性。更新后的清单有 **25 项行为问题、8 项功能缺口、4 项发布与验收事项**。

- **旧删除任务可以跳过新申请的冷静期。** 本地 workerd/D1 用正常取消和再次申请接口。新记录把删除时间延到未来，已开始的旧任务仍删除该测试身份，并把新记录标为已清除。归入 F6，验收时需同时覆盖取消、取消后重申、部分失败和重复执行。
- **更换自托管部署后，旧会话会让新门禁放行。** 保存部署 B 后，组件确实重跑发现，但 A 的有效组织会话直接放行。无会话对照会要求登录 B。F20 的隔离测试只验证了门禁和界面结果。组织列表路径也缺少 issuer/受众匹配，跨服务实际接收结果待验收。
- **Browser 的非活动档案改密入口确实可达。** 默认宽屏状态栏/侧栏的账号管理可选中档案 B，而无需切离 A。真实对话框探针确认提交 B，前一轮实际 Vault/Registry 探针确认 A 仍活动但 Vault 改为 B。Tauri 同一表单也可提交，不过原生操作要求先解锁 B，归入 F24。
- **两个旧结论的边界。** 删除队列的单个失败只占一个槽位，持续饥饿需要最早一批长期占满。同步重建测试证明同一有效 bearer 可建立全新空间。已有设备若固定了同步版本，见到空 registry 会报回滚；当前证据不支持旧同步记录自动恢复。
- **Tauri 锁屏的具体表现。** 密码档案能收到密钥，但 Tauri 锁屏隐藏恢复按钮。只有直接调用 store action 时才会出现 `vault-not-provisioned`。因此用户体验是找不到兑换入口。

## 旧问题的误判与边界

- 2026-10-30 的 6 个修复项仍有通过的回归证据。空闲动作取决于焦点的旧 F4 属于既有产品策略。旧 F7 的重复通知结论继续按低影响历史边界处理。此处编号与下面的 11 月编号独立。[10 月修复记录](./2026-10-30-account-lifecycle-repair.md)
- 11 月旧问题均保留原有用户结果。F2 限定在默认移动与窄屏入口，宽屏 Web 的身份页提供独立入口。F3 有两层问题。确认文案区分了订阅和配对，却夸大了 Capacitor 上的订阅操作，实际只清除当前配对。F4 是回跳事务丢失，认证 state 校验仍在。F5 证明门禁忽略远端结果，设置页会尝试打开 end-session URL，但 Web opener 没有反馈是否打开成功，issuer cookie 状态需单独验收。F8 的前提是自托管 issuer 只发 `sub` 等可用身份信息，显示字段可合法省略。[11 月历史复审](./2026-11-17-account-login-registration-adversarial-review.md) · [OIDC Core 标准 claims](https://openid.net/specs/openid-connect-core-1_0.html#StandardClaims)
- 默认 7 天只反映当前签入配置，该期限可配置。Apple TN3194 明确说明了备用流程。没有可撤销 token 时仍履行删除，再引导手动撤销并处理其通知。应验收发行选择的路径，现有源码审查无法推定 App Store 审核结果。[Apple TN3194](https://developer.apple.com/documentation/technotes/tn3194-handling-account-deletions-and-revoking-tokens-for-sign-in-with-apple) · [Google Play 删除要求](https://support.google.com/googleplay/android-developer/answer/13327111)
