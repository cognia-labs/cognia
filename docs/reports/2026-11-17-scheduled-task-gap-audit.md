# 定时任务现状、问题与业内实践对照

日期：2026-11-17（Asia/Shanghai）。范围：当前工作树；审计与诊断，不修改产品实现、不操作用户任务。证据账本复用 [2026-10-22 ledger](../evidence/2026-10-22-scheduled-task-implementation-audit.md)，本轮以 G8、O30 起的新条目为准。旧记录中的修复和验收不直接作为当前行为证明。

## 判断

当前定时任务的功能面已经比较完整，最需要补的是**执行可靠性、跨平台语义一致性和失败后的处理闭环**。已有 cron、一次性、间隔、事件、重试、并发策略、补跑、通知和常驻 Host，继续扩充触发器不是当前首要工作。

首轮得到 **11 条具体发现**：7 条由当前调度器/数据库/表单的行为检查复现，4 条由 Rust 生成器或完整源文件隔离 harness 复现。其中“暂停被覆盖”和“并发计数丢失”共享读改写统计的根因。重启后的重试/排队属于已确认的可靠性缺口，不能据此推断所有普通定时任务重启都会丢失。

首轮现有定向回归 **11 suites / 448 tests 全通过**；首轮新增反例 **7 个失败、2 个正向对照通过**。因此“已有测试绿”与“无人值守可靠性充分”目前是两件事。

## 建议实施顺序与验证

1. **先阻止错误或失控执行。** 修 F4、F7、F8–F11、F6；统计与排期等全部整行 writer 使用窄字段事务/CAS，并给 drain continuation 加生命周期检查，OS 转换不支持就拒绝，编辑失败保留原定义。每项将当前反例改为永久同目录回归；OS 转换补跨语言/跨平台 golden vectors。
2. **再建立持久执行闭环。** 在现有 account DB / 调度器中扩展 occurrence、attempt、queue；不要另造第二套 task 配置。将 cursor advance 与入队原子化，修 F1–F3；定义发生过外部效果但未结算的处置。先通过真实进程终止重启，再验收实际 Host 持久源。
3. **随后统一恢复与产品表达。** 接入 workflow misfire 策略、latest 合并、失败收件箱、积压告警、通知交付回执和日历例外。补运行载体/Host 离线/下次可执行时间的明确说明。
4. **最后考虑自动故障接管。** 以持久账本和副作用幂等为前提，做网络分区、旧 owner 恢复和 fencing 演练。当前证据不足以支持仅为这些问题整体替换调度引擎。

### 首轮需要纠正的证据与建议

- **F1/F3 是可靠性能力缺口，P1 是面向无人值守场景的建议顺序。** `stop()` 后替换调度器对象，不是实际进程死亡；未找到所有队列/重试都必须跨重启恢复的现有明确承诺。保留事实，避免写成已验证违反统一生产 SLA。
- **F2 的窗口得到更强模型证据，仍无 SIGKILL 验收。** A0 从公开 `createTask` 创建 once，由可控 driver 的实际 `onDue` 回调进入 claim；在真实事务提交后阻塞，确认 runCount=1、nextRunAt 清空、执行记录为零，再替换实例，仍未恢复原工作。自动 due 正向对照可以完成并入库，因此不再仅依赖 storage-only seed 推导可达性。
- **F7 当前 admission 缺陷保留，但永久测试需响应取消。** 原反例旧 executor 忽略 abort，只能证明 replacement 被跳过，不能要求非合作 executor 立即让出真实执行资源。新 A7 的旧 executor 响应 abort 并退出，实际活动数不超过 1，replacement 仍被跳过；修复时应增加“退出先于替代启动”的正向断言与不响应取消的有限等待策略。
- **A4 被否定，不增加为缺陷。** [现有契约](../../lib/scheduler/occurrence.ts#L20)明确把 retry 当成独立 start，[注释](../../lib/scheduler/occurrence.ts#L69)明确其 scheduledFor 是 retry time。期望 retry 原样保留原槽位的断言不符合当前契约。若未来引入 immutable occurrenceId + attemptId，必须同时审查重试 cadence、Bot record ID 和 workflow admission；不能简单复用同一 idempotency key，否则可能只复用已失败结果。
- **F6 的证据收窄。** RTL 仅复现输入框从 0 变 3，保存行为目前为源码推导。报告已修正措辞，并修复双竖线破坏 Markdown 表格的问题。
