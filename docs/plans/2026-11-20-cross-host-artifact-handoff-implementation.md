## 阶段 1　修复现有读写链路

### 1A · F01 和 F02 共用完整读取契约

1. **F01 先阻止静默截断。** 保留 `files_library_get` 供预览，消费 `textTruncated` 并明确显示预览范围。下载、ZIP、复制和聊天引用走完整读取或明确失败。ZIP 在打包前列出不可读取的条目，用户确认缩小范围后才另行导出。聊天引用超出自身限额时单独给出结果。
2. **为完整读取协商版本能力。** Host 把条目解析为一次已授权的内容快照，返回短期 `readId`、字节长度和 SHA-256。Canvas/Artifact 从一次内容快照编码完整 UTF-8，避免在 JS 字符边界截取。后续分块绑定同一设备、条目、句柄与 offset。客户端校验分块位置、字节长度与最终摘要。配对现有 10 MiB 传输上限继续适用。
3. **F02 从 Host 固定读取源。** 优先使用现有捕获账本的不可变字节，或在运行生产者结算后获取受控快照。对仍可写的磁盘路径，能协调的写入使用版本检查和写入协调。外部写入场景检测文件身份与内容版本变化，无法证明读取源稳定时返回 `source_changed` 或 `stable_read_unavailable`。同一描述符可固定被 rename 的文件对象，仍需防止同 inode 原地改写。仅对拼接结果补哈希无法建立源版本。
4. **处理旧端和取消。** 对旧 Host，截断正文和无版本的多块读取提示到支持的桌面端。新 Host 对无法保证完整性的旧客户端请求明确拒绝。成功、取消、超时断线后清理读取句柄。重试重新校验授权，版本变化要求从头读取。若回退完整读取能力，仍保留拒绝截断和不稳定输入的保护。

Files 和 Native Files 维护人交付。覆盖多字节、空文件、字节上限、提前 EOF、rename、等长原地改写、断线和旧端。真实 Tauri 使用临时目录执行并发测试。 [配对预览与导出](../../lib/files-library/remote/remote-ops.ts#L76) · [现有分块客户端](../../lib/files-library/remote/client.ts#L388) · [原生读取](../../crates/cognia-files/src/files.rs#L1137)

### 1B · F03 按清单摘要选择和保存 canonical 字节

**逐个验证候选，再做选择。** 对目标缓存、已提交 staging 和该接力允许的在线来源，分别校验长度、MIME、SHA-256。只有所有候选都失败才拒绝接力。预检只核验，目标 accept 才写入媒体并持久化引用。已有同键异内容时，用独立的 canonical 版本引用保留准确字节，禁止覆盖仍被原会话使用的媒体。

先校验原 wire envelope 和 ticket digest，再用一份目标内部的 URI 映射投影消息。重试使用同一持久映射或重新核验目标副本。HostState 导入和独立移动接收共用匹配规则，媒体引用写入后才返回 accepted。复用现有 ticket wire 格式与所有权提交；旧目标无法保存准确版本时继续显式拒绝。测试同键异内容、正确/损坏 staging、历史 ticket、并发重试与接收端重启。F04 工具附件的投影和 F05 历史版本的打开各自跟踪，首版发布入口聚焦已选 workspace 文件。 [附件预检](../../lib/thread-handoff/attachments.ts#L96) · [HostState 导入](../../lib/sync/host-state-store.ts#L1232) · [独立移动端接收](../../lib/thread-handoff/standalone-receiver.ts#L48) · [媒体写入行为](../../lib/db/message-media.ts#L49)

### 1C · F06 在同一事务提交共享附件和事件

顺序固定为**对象存储完成并通过校验 → 数据库事务提交附件和事件 → 广播**。上传处理持久记录校验结果。追加事件时，服务端从规范消息提取共享附件引用，验证组织、工作区、会话、作者和可绑定状态。在同一 PostgreSQL 事务中把本次附件标为 available、绑定事件并追加事件和现有队列副作用。对象存储 I/O 在事务外。相同 operation ID 返回原结果，作者或规范参数冲突时拒绝。

服务端先部署，把保护接入现有追加入口。旧客户端随后发出的 commit 凭相同事件 ID 幂等成功。旧 pending 附件经服务端复核已有对象后才允许绑定。已经可用的旧引用仍按同会话权限读取。已发布但尚 pending 的历史消息尝试恢复提交，无法核验时持久记录不可用的附件占位和重试标记，再推进游标。接收端继续处理无关事件，后来恢复的附件按原 ID 补齐引用。导入草稿保持在全部附件就绪后激活。回退客户端时保留服务端的原子保护。

Collaboration 维护人交付。真实 PG 测试多附件部分失败、事务回滚、提交响应丢失、两个成员并发同步及旧客户端的重复 commit。 [发送顺序](../../lib/collab/shared-run-coordinator.ts#L510) · [事件及广播](../../crates/cognia-collab-server/src/chat_api.rs#L2063) · [附件提交](../../crates/cognia-collab-server/src/chat_api.rs#L3477) · [接收投影](../../lib/collab/shared-chat-sync.ts#L565)

### 版本、提交与授权

```text
源 Host A 选定并冻结文件字节
  -> 协作服务校验字节并持久化，提交后返回 versionId 和 SHA-256
  -> 独立控制端携带固定版本，向目标 Host B 发新任务
  -> Host B 重新授权，从持久服务冷读、验证、原子落盘
  -> Agent 启动，使用此次运行的文件输入
```

- **固定版本。** 服务拥有 `artifactId` 和不可变 `versionId`。引用包含服务实例、`orgId`、`workspaceId`、`artifactId`、`versionId`。服务返回权威长度、SHA-256、MIME、发布者与来源 run。显式发布同一产物的新内容产生新 `versionId`，原引用仍定位旧版。同名仅用于展示。凭证、绝对路径和对象存储键留在其所有者内部。
- **提交与重试。** 预留绑定工作区、发布者、幂等键、目标产物与预期字节。重试相同参数返回原上传或原版本，参数变化返回冲突。上传先写入服务生成的不可覆盖对象，核验后事务提交版本。列表和调用端只消费 committed 版本。超时或取消先用状态转换关闭提交资格，清理任务再对照对象与元数据回收孤儿。提交和清理争用同一预留状态，胜方决定版本命运。响应丢失时按同上传 ID 查询，存储写入结果不确定时复核对象再推进。
- **有界传输。** 试点建议单文件 50 MiB，采用现有协作附件上限作为初始验收规模。按固定缓冲流式上传与下载。首版中断时使用同 ID 重试完整请求，跨进程分片续传留待后续迭代。试点开通前配置工作区总配额、并发上限、上传时限与保留期。重试与清理占用也计入配额。
- **分层授权。** 协作服务按当前组织/工作区权限分别核验 `artifact.read`、`artifact.publish` 和撤销动作。可信目标 Host 验证实际运行身份、工作区和已接受的版本输入，用自己的同身份协作连接读取。两端必须解析到同一受验证用户。客户端自报 run ID 仅用于审计关联，服务凭证留在可信 Host。已提交的文件在目的路径按运行隔离，所需输入未校验完成时 Agent 无法启动。
- **撤销与清理。** 每次读取或重试重新授权，最终物化前再检查版本和权限。撤销后拒绝新的读取和物化，已落地副本随目标运行管理。删除源会话或源路径时保留已发布版本。版本过期或撤销时先禁止读取，再持久记录对象清理任务。依次测试存储中断、权限变化、重启、对象丢失或摘要不符。目标失败时清理临时文件。
- **文件与外发边界。** 仅处理主动选中的普通文件。源 Host 和目标 Host 限定可信工作区根，拒绝符号链接逃逸，遵循现有敏感路径、组织外发和适用审批。策略不允许外发时拒绝发布。后续送入模型时走现有模型数据权限。审计记录操作、结果、主体与关联 ID，常规日志与指标省略内容、路径、摘要和令牌。

### 部署与回退

协作服务新增表和权限记录，具备工作区查询索引、版本唯一约束、幂等约束与清理索引。使用已有迁移路径做增量部署，用户显式发布所选历史文件。新服务先上且能力默认关闭，随后只对试点组织与工作区开放。桌面发布和 headless 消费分别声明能力，能力缺失的客户端显示具体原因。

发现错误版本、授权越权或提交前可见，立即关闭新发布和新任务使用入口。版本数据和对象保留用于校验及恢复；只读路径在鉴权与完整性正常时继续提供既有版本下载。需要暂停读取时只暂停相关能力。部署端联合备份数据库及对象，恢复后对账孤儿、缺失对象与 tombstone。记录发布、读取、物化的状态、耗时、字节数、内存峰值和清理积压，按动作、端类型及有限错误类别聚合。完整性或越权问题阻断试点扩大。

## 阶段 3　源 Host 下线后，目标 Host 从冷态取回旧版

同一次验收运行真实桌面 Host A、真实 headless Host B、独立的协作服务和持久对象存储。独立控制端能发起 B 的新运行。B 使用新数据目录，确认文件不存在于目标工作区、临时目录和媒体缓存。现有两个 Playwright project 覆盖不同运行环境，专用用例还须让 A 和 B 同场并验证实际下线。 [现有验证配置](../../playwright.dual-host.config.ts) · [Harness](../../tests/dual-host/harness.ts)

| 验收                    | 操作和通过条件                                                                                                                                                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1 · 发布两个版本       | A 的已结算运行生成测试文件。分别用二进制文件和含多字节字符的文本跑本用例。测试控制端独立计算原始长度和 SHA-256。发布 v1 后覆盖同一源路径，显式发布同一产物的 v2。提交回执返回不同 version ID 和摘要。B 仍未取过文件。               |
| A2 · 停止 A             | 停止 A 的执行进程、侧车与配对或 relay 路径。进程记录、健康检查和已有控制连接证明 A 不可达。协作服务、数据库和存储保持在线。                                                                                                         |
| A3 · 在 B 冷读 v1       | A 下线后才创建 B 的新运行并明确选 v1。服务访问记录证明 B 请求 v1，目标记录先完成校验和落盘再启动 Agent。由 QA 在 Host 侧独立读文件并计算长度与 SHA-256，同时让目标运行内的测试动作实际打开输入文件并计算，两者严格等于 A1 中的 v1。 |
| A4 · 重启服务并复查     | A 继续下线，重启协作服务及测试存储实例，保留持久卷和数据库。在 B 清空本地读取状态后分别读取 v1 和 v2，各自匹配摘要。至少用一套真实 S3 兼容后端执行全流程，另记录独立本地卷部署的结果。                                              |
| A5 · 注入传输和数据故障 | 上传中断时版本不可列出、不可读取。丢弃提交响应后同 ID 重试只产生一个版本。对象缺失或篡改时 B 无最终输入、Agent 不启动。覆盖大小上限和上限加一字节、B 下载途中重启。                                                                 |
| A6 · 权限和清理         | 同项目只读用户可读授权版本，发布被拒绝。另一项目、撤销工作区成员资格或撤销版本后，新读和新运行取回失败。移除源路径后有效版本仍可独立读取，重复清理不影响其他版本。                                                                  |

每次保留组件版本、Host ID、run ID、工作区和 version ID、独立摘要、服务提交/读取回执及各步骤时间。**A2 与 A3 必须在同一条时间线上证明源 Host 已停止且目标此前未读过。** A1–A6 全部通过，且阶段 1 回归通过，才扩大试点。
