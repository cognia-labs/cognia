# Cognia Mesh 跨设备 Agent 工作区：评审修订稿

状态：需求已评审并收敛，未开始实施（4 个已确认缺陷已单独修复）。创建：2026-10-31（Asia/Shanghai）。输入：2026-10-31《Cognia Mesh 跨设备 Agent 工作区需求评审稿》REQ-01～REQ-09（Qoder 对比范围）。相关决策：[ADR-0244](../content/docs/en/adr/0244-a-remote-run-has-stopped-only-when-its-worker-says-so.md)（停止与恢复）、[ADR-0245](../content/docs/en/adr/0245-a-paired-device-is-granted-workspaces-not-a-host.md)（工作区授权）。证据：[证据台账](../evidence/2026-10-31-mesh-cross-device-workspace.md)。

## 1. 结论

原稿方向正确：在现有 Worker、远端 Session、派发租约、设备控制台和 Attention 上扩展，而不是另起一套。但原稿把九项当成一个需求，核对代码后：

- **真正的新问题有三项**：REQ-02 工作区授权、REQ-03 远端工作区引用与委派、REQ-05 停止与恢复安全。REQ-05 风险最高，原稿对它的表述准确。
- **大部分已具备的有三项**：REQ-01 配对与身份、REQ-04 独立执行、REQ-08 远端配置。原稿低估了现状，真实缺口很窄。
- **与跨设备无关的有两项**：REQ-07 Codex 导入、REQ-09 交付团队模板，来自 Qoder 对比，拆出单独排期。
- **另有 4 个已确认缺陷**，不等评审已单独修复（§6）。

| D5  | 停止证明 = Worker 自我隔离（租约过期 + 声明的宽限期）或显式停止确认；两者都没有则转人工。不做工具级幂等键。                                                       |

| D9  | 委派目标通过 **Composer 目标选择器**指定（设备 + 工作区）；`@` 仍只表示 Runtime/Squad；发送时把 Host 固定到这次运行。                                             |

## 4. 修订后的范围

### M1a：执行安全与目标固定

- **REQ-05 停止与恢复**，按 [ADR-0244](../content/docs/en/adr/0244-a-remote-run-has-stopped-only-when-its-worker-says-so.md)：
  - 停止三态（已请求 / 已确认 / 未确认），运行先 `cancelling`、最后才写 `cancelled`。
  - 暂停声明类型：可中断（`turn-interrupt-v1`）或等当前 turn 结束；无法完成为 `pause_unconfirmed`。
  - Worker 自我隔离（`worker-self-fence-v1`）：每次调用工具前确认租约有效，续约失败或控制断开就中止 turn。
  - 租约 `dispatchEpoch`：续约、结算、事件推进、结果投影都比较 epoch；旧 epoch 的迟到写入被拒。
  - 统一恢复规则：三条路径都要求停止证明 + safe checkpoint，否则进入人工处理。
  - 撤销：立即拒绝新操作（含出站帧），排队任务派发时重新校验，待处理中断失效；撤销不宣称已停止。
- **REQ-03/04 目标固定**：
  - Composer 目标选择器（设备 + 工作区），发送时重新校验身份、授权、在线、能力；不可用时提供等待/取消/重新授权/显式改选，从不静默回退到本地或其他设备。
  - 运行记录发起人、执行设备、工作区、父子任务、attempt、远端 Session；帧带来源与 attempt。
  - 切换选中的 Host 不改变已接纳运行的目标，原运行经管理通道保持实时（D13）。

**M1a 验收（SC-03/04/05）**：

- 受控双 Worker 场景：旧执行可能仍在产生副作用、又没有停止证明时，第二次执行不会被标为安全恢复并启动。
- 断网、主动撤销、Host 重启、审批等待各有一份真实环境证据。
- 切换 Host、重连、重复事件不串用 Session、不重复结算、不改变执行目标；旧 attempt 的迟到结果不覆盖新 attempt。

### M1b：授权与引用

- **REQ-02 工作区授权**，按 [ADR-0245](../content/docs/en/adr/0245-a-paired-device-is-granted-workspaces-not-a-host.md)：`(device, workspaceId, files.read|files.write|sessions.read)`；Host 从自身可信来源解析路径，请求方路径不能扩大范围；执行类授权仍为 Host 级（D4）。
- **REQ-01 补强**：受限邀请；所有客户端在邀请被消耗之前用连接上的证书固定 SPKI；配对房间在兑换时关闭；Worker/Host 对应关系和版本兼容判断覆盖所有设备行。
- **远端 `@file` 引用**（D10）。
- **REQ-06 安全三项**（D12）。

**M1b 验收（SC-01/02/06）**：

- 未授权 root、绝对路径、`..`、symlink、Windows 路径变体、工作区重绑定都不能扩大权限。
- 只读授权不能经另一工具变成写入或进程执行。
- 授权变更后，排队任务重新校验。
- 过期或重复使用的邀请不能建立身份；撤销后重新配对不复用旧授权。
- 多端同时处理审批只产生一个有效决定；历史审批不能授权新的 attempt。

### M2 / M3（原稿顺序保留）

- **M2**：完整 REQ-06（结果待查看、搜索/过滤/历史、跨来源去重）。
- **M3**：REQ-08 的剩余缺口（删除 CAS、额度就绪检查、资源同步预览）。

### 不在本稿范围

- 浏览器 profile 归属（D8）。
- 跨组织协作、自动克隆仓库、手机后台 Agent 执行、运行中进程迁移（与原稿一致）。
- 强制接管未确认停止的运行（D15）。

## 5. 横向要求（保留原稿）

- 日志与审计能关联发起人、目标、授权、运行和 attempt；记录拒绝、撤销、重试和恢复依据；不记录配对秘密、凭证或不必要的原始敏感内容。
- 所有对外模型发送继续经过现有 PII gate。
- 关键流程覆盖键盘操作、可访问名称、中英文文案、旧客户端兼容和版本能力拒绝。
- 单元测试通过不能替代真实双设备验收。

## 6. 已单独修复的缺陷

| 缺陷                                                                                                                        | 修复                                                                                                                                                                | 状态                                         |
| --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| 远端 `write_text_file_confined` / `ensure_dir_confined` 直接信任请求方的 `allowedRoots`                                     | 由 Host 可信根目录约束（桌面注册表；headless 用 spawn policy），请求方只能收窄                                                                                      | 实现中：headless 分支跟进修复                |
| `root/missing/../../x` 先过祖先检查，`create_dir_all` 后写到根目录外                                                        | 在创建任何目录之前拒绝未解析的遍历；创建后再次检查                                                                                                                  | 已实现，待提交                               |
| 派发后，取消和权限回答发往当前活跃 Host，而不是运行所在的 Host                                                              | 运行与决定固定到派发时的 Host，经按 Host 建立的管理通道投递；无法投递时返回 `host-changed` / `host-unreachable`，从不改投活跃 Host；admin lease 与命令固定同一 Host | 已实现，待提交                               |
| Codex `approval_policy="never"` 在"覆盖"策略下被导入为 `bypassPermissions`；`danger-full-access` 关闭沙箱；会话导入失败被吞 | 权限绕过、关闭沙箱/工作区约束不再随导入生效（草稿与 apply 双重拦截）；会话失败显示为警告                                                                            | 实现中：改为只剔除 allow 规则、保留 ask/deny |

已知遗留：本机发起的运行在切换到远端 Host 后，取消会被拒绝（`host-changed`），而不是投递到本机。该问题并入 M1a 的目标固定。

## 7. 拆出的独立小计划（M1a 之后排队）

**REQ-07 选择性导入**

- 逐项预览（来源、目标、兼容性、冲突）和逐项选择。
- 逐项结果与仅重试失败项。
- apply 使用已预览的数据，不重读源。
- 设置的"保留两者"目前实为跳过，需修正语义或文案。
- 命令/Skills/MCP 覆盖前检测用户已修改的目标。

**REQ-09 软件交付团队模板**

- 新增开发 + 测试 + Review 组合模板，声明角色职责、输入输出、依赖、交付物和完成条件。
- 模板默认开启 `taskReview`。
- Review 批准要求证据：通过 `evidence.validate` 和真实检查结果。
- 实例化前检查 Runtime、工具、仓库和目标设备是否就绪。
