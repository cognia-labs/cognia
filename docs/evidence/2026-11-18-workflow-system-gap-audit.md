## Original request

> 帮我审查现在的工作流系统，看看差什么功能，或者存在什么问题，以及和其他模块的联动之类的是否存在问题，并且对照业内的优秀实践

## 审查结论

**对抗复核后保留原 18 项编号，新增 8 项，合计 26 项（16 P1、10 P2）。** WF-18 由 P2 升为 P1，已复现来源下线会阻断订阅者自己的手动运行。重点收窄了 Webhook 成功响应的含义、loopback 监听的产品边界、Scheduler 独立放置规则，以及 Agent Plan 按草稿运行的历史契约。详细裁定和被排除的推断见「逐项对抗复核」。

**应先修复运行契约，再扩节点和触发类型。** 工作流已经拥有编辑、不可变发布、复用、运行历史、人工等待和 Host 执行。高影响问题集中在三个边界：恢复后是否继续同一次运行，生产事件是否由同一个已发布版本决定，调用方是否拿到了可追踪的实际运行。

- **恢复**。故障注入复现了 Cron 运行在恢复时改走 Manual 分支，以及同一触发下恢复时执行了原先未选中的分支。
- **发布与触发**。合成验证复现了草稿事件过滤器改变生产匹配、完整预览发出 completion 事件，以及发布旧保存版本和保存丢失 dirty 标记。
- **模块联动**。Scheduler、Mobile、Webhook、Agent Plan、Approval 各有明确断点。Chromium 抽查了建图、保存和手工运行。原生重启、配对投递和真实审批仍需验收。

P1 表示可能执行错误分支或版本、漏跑、误触发生产、错误处理人工决策，或对关键入口给出错误成功信号。P2 表示局部 UX、运营和管理缺口，或适用范围更窄的路径差异。分级按主路径影响评估，缺陷发生频率与线上影响未测量。
