## Original request

> Run spike S1 from docs/plans/2026-11-01-convergence-phase-0.md §3: answer the five questions of ADR-0250 §2 with measurements and recommend 2a or 2b

## Fixed acceptable ranges (written 2026-11-01, before any measurement; never edited afterwards)

Committed in the first ledger commit on `spike/local-brain-s1`. Any later change to this section is a
spike-rule violation; reviewers compare it against that commit.

### Datasets

- **R (real-matched).** Row counts and inline value sizes per table matched to the largest real local
  desktop database on this machine (WebKit `IndexedDB.sqlite3`, 187,654,144 bytes, Dexie version 250,
  38,163 rows, 36,952,285 bytes of inline values, plus 3,657 blob files totalling 166 MB in
  `petMediaPacks` / `petModelFiles`). Synthetic content, real schema, real write paths.
- **H (heavy chat stress).** R plus 2,000 sessions and 200,000 messages (mixed text and tool results,
  about 300 MB of message payload). The real database holds only 28 sessions and 42 messages, so it
  under-represents a heavy chat user; H is that user.

### Operations (the real code paths, not stand-ins)

- **Session list:** the sidebar's first page via `readVerifiedSessionListRows` (`lib/db/session-list.ts`).
- **Session open:** session row plus `listRecentMessages(sessionId, 50)` (`lib/db/messages.ts`).
- **Message append:** `commitMessageDelta` with one upserted message, durable when it resolves.

Each measured warm: 20 warm-up iterations, then 200 timed, sequential. Report p50, p95, throughput.
"Baseline" is the same operation on Dexie inside a real WKWebView (WebKit IndexedDB, the engine the
Tauri window uses) on the same dataset. "Brain" is Dexie over the brain's store with its default
durability backend (`sqlite-v5`) capturing every commit. "Client-observed" is the same call made by a
client through the companion server's loopback RPC to the brain (the 2a path).

### Question 2 ranges (startup and memory)

| Metric                                                                                                                            | Dataset R                      | Dataset H       |
| --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ | --------------- |

If the full Tauri cold start cannot be measured inside the time box, the added cold start is bounded
from above by brain spawn → data restored → bridge `hello` → first list RPC answered, measured under
the real `cognia-server` supervisor, and the ledger says that it is an upper bound.

### Decision rule (from the plan, restated)

All five questions without a blocker that phase 2 cannot remove, and questions 1 and 2 inside these
ranges → recommend 2a. Any blocker phase 2 cannot remove → recommend 2b, naming it. A question still
open at the time box is recorded as unknown with an estimate, and the recommendation says how much it
leans on that unknown.

R blobs digest-equal after a cold restore on `journal-v4` (seed 23.4 s, longest gap 910 ms) and

## Problem frame

<!-- One paragraph: the problem we are choosing to solve now, the outcome that
would show it is solved, and what is explicitly out of frame. Cite IDs. -->

Choose the phase-2 shape for ADR-0250: 2a (desktop WebView becomes a client of a local Node brain,
which owns the data) or 2b (the kernel runs inside the WebView, which stays the desktop authority). S1 is
solved when each of the five questions has a measured answer or a recorded unknown against the day-1
ranges, and a recommendation follows from the decision rule (G1). Out of frame: building either option,
editing ADR-0250, measuring 2b's own phase-2 costs (S1 only measures today's WebView as the 2b baseline),
and fixing the defects found (O4 goes to 0b as B10).
