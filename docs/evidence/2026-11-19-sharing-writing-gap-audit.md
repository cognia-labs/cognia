## Problem frame

以作者起草、局部改稿、保存版本、交付或邀请成员，直到接收者首次打开和反馈为主线。共享覆盖聊天公开快照、文件交付、成员制共享聊天、Canvas 协作，与 Artifact 和 Sites 的交付边界相交。写作覆盖写作模式、Markdown 文档 Artifact、Canvas、导出与第三方文档交接。独立的终端、浏览器控制、系统分享接收及文档解析矩阵由各自子系统覆盖。用 M1 衡量本轮输出。

## 结论

Cognia 已有可用的聊天快照、文件交付和本地 AI 写作。它的差距集中在**能否可靠交付同一份文稿**。当前从聊天到 Artifact、再到 Canvas 和导出时，作者可能跨多个对象及版本。投递公开快照时需要重新核对内容，发送 Canvas 协作链接后，新设备仍无法从该入口加载文档。建议先修复会发错内容、打不开文档、改错文字和保存旧版本的问题，再扩展共享审阅能力。

### 缺陷与缺口

优先级 P1 指高影响的常规路径故障或信息完整性问题。P2 指路径可用但覆盖有限，或需要显式处置的恢复及管理问题。证据来自合成数据探针或当前可达源码，后者需要相应环境补验。

| ID  | 优先级与证据                | 用户影响与边界                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S01 | **P1 · 探针复现**           | **预览与发布可以是两份正文。** 真正的分享弹窗显示 A，点击创建时调用 builder 得到 B 并交给发送端。单会话 builder 每次读消息。多会话已经缓存预览正文，并在发布前重检来源；这一缓解不能直接推广到单会话。文件 manifest 由发送端后置组装，预览缺少最终文件清单。 [预览和创建](../../components/share/share-link-dialog.tsx#L241)、[单会话](../../components/data/export/single-export-dialog.tsx#L279)、[批量缓存](../../components/share/multi-conversation-share-dialog.tsx#L26)、[附件组装](../../lib/share/client.ts#L272)                                  |
| S02 | **P1 · 探针复现**           | **单条消息的引用卡片无法创建加密链接。** 桌面和移动共用的动作生成裸 `chat-quote`。真发送端需要来源证明，合成样本在发请求前得到 `Personal chat share snapshot has no Host projection proof`。PNG 走独立路径。应复用经过授权的消息和标题投影，保留现有校验。 [引用卡片](../../components/share/quote-card-dialog.tsx#L162)、[投影校验](../../lib/share/personal-snapshot.ts#L16)                                                                                                                                                                              |
| S03 | **P2 · 探针复现及源码**     | **预览内点击创建，错误会被藏到原表单。** 模拟连接失败后，在预览内看不到报错，关闭预览才显示。成功分支的撤回失败也只更新同一错误状态，成功页没有对应文案。直接创建时，已失效媒体数只在预览分支渲染。 [状态更新](../../components/share/share-link-dialog.tsx#L327)、[成功与预览分支](../../components/share/share-link-dialog.tsx#L397)、[表单错误](../../components/share/share-link-dialog.tsx#L551)                                                                                                                                                       |

### 初审建议顺序与验收

1. **先修正确性。** 公布的正文和附件逐项等于作者确认的快照，编辑期间新增的内容必须重新预览。引用卡片在正常权限下能成功发布。模拟失败时，在当前弹窗说明是否创建、是否撤回，以及可执行的恢复动作。Canvas 在继续打字、换文档、切换选区时保持请求基线，正确应用中英文、单行、多行和列范围。每个保存、恢复、复制和导出动作消费最新有效缓冲。保存历史在无变化时不增长。
2. **跑通文稿交付。** 接收者用全新浏览器配置打开有权限的 Canvas 文档，能够看到正确文档和工作区。把「发送固定版本」和「邀请一起写」加入同一个文稿入口，标明当前共享对象、来源版本、目标人群、附件和到期。支持来源撤回追踪、创建失败恢复，公开快照继续使用现有加密与生命周期合同。
3. **按需求增加审阅与多人写作。** 先接文稿评论和共享版本，再做标注、回复、已解决状态、离线更新恢复及多端冲突体验。验收用两个不同角色、无本地副本的首次加入、离线双方编辑、刷新后重连、权限调整及评论锚点迁移。原生富文本、多页写作和样式模板的优先级取决于写作用户需要的交付物。可并行修补现有 DOCX/PDF 的中英文和表格保真。

1. **先修对外快照和正文完整性。** S01、S02、W02–W04、A07。使用同一份确认正文和附件生成上传包，保持发送时权限复核。AI 基线绑定操作发起的正文和选区，处理等待期间的人工修改和编辑器切换。保存、恢复和交付统一消费已确认的最新文本。A04、A06 并行做防御性复核。
