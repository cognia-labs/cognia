## Audit result and scope

Snapshot: 2026-11-18, macOS workspace, HEAD `b50c5c9501263e3abf20f5792c98756cdc675687` plus the existing shared working tree. CodeGraph had no index, so navigation used source searches and direct reads. No product code, settings, credentials, Git history or account state was changed. The only task-owned durable additions are this ledger and eleven adjacent probe scripts. The adversarial review used HEAD `2e6da23843f9134e8e6865d8f32a213d2402d5ad` plus the shared tree; the intervening committed change in the original audited paths was a dialog color class, with no functional effect on the original probes. A separate report was necessary because no open voice/TTS audit ledger existed; the meeting audit covers a different product flow.

Cognia has substantial voice infrastructure. The immediate weaknesses are lifecycle correctness, transcript integrity, privacy classification and consistency across surfaces. Provider counts describe selectable implementations, not real-provider qualification. `lib/speech/module.ts` itself records `acceptance.realSmoke: "pending"`.

Evidence labels below:

- **Reproduced logic**: an executable probe exercises current production logic with controlled platform boundaries. It does not establish physical microphone behavior, real cloud billing or production data loss.
- **Source finding**: a reachable code path supports the conclusion, but the complete user flow was not executed.
- **Conditional boundary**: the missing guard is demonstrated; exploitation or disclosure in a real browser is not established.
- **Product gap**: a suggested capability, not an accepted requirement or necessarily a defect.

Necessary qualifications:

- F01 uses the actual orchestrator, OpenAI adapter and PII matcher with a captured transport, not a real HTTP call. Chat/selection callers do not add a raw-text check (`lib/tts/speak-chat-message.ts`, `speak-selection.ts`). Pet speech checks raw text first; `synthesize()` and IM delivery also have original-text checks. Do not generalize F01 to every speech entry point. The same ordering is present in `speakStream`; its cross-fragment privacy behavior needs dedicated regression cases.
- F02/F03 use actual installed `@ai-sdk/google@4.0.112` event mapping and production persistence code, with injected storage. They establish faulty saved-message projection rather than an observed production Dexie incident. The dialog's `deliveredTurns` set also ignores later updates to a previously delivered ID (`live-voice-dialog.tsx:208`).
- F04 establishes late socket/capture creation with injected media/network boundaries. It does not prove that an already stopped real MediaStream resumes capturing sound.
- F05 is partly mitigated by the dialog cancellation catch stopping preflight stream tracks (`live-voice-dialog.tsx:440-449`). The confirmed defect is controller state/resource cleanup, not proven indefinite microphone recording after the real UI's Hang Up.
- F06 does not bypass tool execution approval. The controller probe establishes a gate/mute composition defect. UI reachability is after approval during execution: the approval modal clears before the execution hold releases, so it must not be described as clicking through a pending approval modal.
- F12 is a locally rejected fragment, not a proven oversized outbound request. With fallback enabled the user may hear an unexpected System voice instead of an error.
- F14 has a source-traced trigger (other chats consume capacity while the current chat is idle and non-platform-bound). An asynchronous recognition `end` variant reproduces F13/F14 too, ruling out dependence on a synchronous fake event.
- F08 requires the final delta and idle state in the same render. The main completion path flushes text and awaits persistence before idle (`agent-chat-events.ts:1730,1815`), which can allow a prior render; not every ordinary completion loses a tail.
- F01 also survives the native-text-gate objection: the Rust proxy checks already transformed JSON (`crates/cognia-tts/src/proxy.rs:448`), not the original text. This remains captured-transport evidence, not cloud disclosure.

## Unconfirmed investigation candidate

**C01 — stale full-history snapshots can race with another writer (investigate at P1).** `persistLiveVoiceTurns` reads history before entering the DB write queue (`persist-turns.ts:167-173`), then calls full transcript replacement. The DB queue serializes writes, not the read/merge/write operation (`lib/db/messages.ts:198,460`). A stale snapshot can omit a newer ordinary row; replacement deletes omitted unprotected rows (`:604-618,667`). Agent-turn-owned sessions and connector/refused-host rows have explicit preservation rules, so this is not an all-session deletion claim. Real Dexie interleaving has not been reproduced; exclude C01 from the 28 confirmed/source-supported findings. Next check: two real writers under fake-indexeddb, both an ordinary session and the protected counterexamples; use an atomic message-delta API if confirmed.

## Sources

All external sources were read on 2026-11-18. Only primary technical documentation supports the comparison.

- S1: [OpenAI — Realtime conversations, interruption and truncation](https://developers.openai.com/api/docs/guides/realtime-conversations). WebSocket clients must stop queued playback and reconcile the heard duration with server history.
- S2: [LiveKit — Turn detection and interruptions](https://docs.livekit.io/agents/logic/turns/) and [Adaptive interruption handling](https://docs.livekit.io/agents/logic/turns/adaptive-interruption-handling/). False interruption recovery and backchannel handling have explicit configuration and deployment prerequisites.
- S3: [ElevenLabs — Stream speech with timing](https://elevenlabs.io/docs/api-reference/text-to-speech/stream-with-timestamps). Incremental audio with character timing provides an alignment contract.
- S3b: [ElevenLabs — Pronunciation dictionaries](https://elevenlabs.io/docs/eleven-api/guides/how-to/text-to-speech/pronunciation-dictionaries). Phoneme and alias support is model-dependent.
- S4: [MDN — SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition). Support is limited and processing can be server-based; explicit on-device recognition is a separate capability.
- S5: [MDN — SpeechSynthesisVoice.localService](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService). System-provided voice lists can include remote services.
- S6: [Google — Live API session management](https://ai.google.dev/gemini-api/docs/live-api/session-management). Connection renewal, resumption handles and context compression solve different continuity constraints.
- S7: [LiveKit — Session traces and metrics](https://docs.livekit.io/reference/agents/session-traces/). Stage-level, turn-correlated latency is an observability reference.
- S8: [sherpa-onnx — Official documentation](https://k2-fsa.github.io/sherpa/onnx/index.html). Local speech recognition across desktop/mobile is a feasible investigation direction, not a selected dependency.

- S9: [Google SDK — LiveServerSessionResumptionUpdate](https://googleapis.github.io/js-genai/release_docs/interfaces/types.LiveServerSessionResumptionUpdate.html). A previous token can resume an older checkpoint; resumable=false does not establish token invalidity.
- S10: [MDN — Request.redirect](https://developer.mozilla.org/en-US/docs/Web/API/Request/redirect). Unspecified redirect mode defaults to follow; the browser fixture verifies the adapter consequence.
- S11: [MDN — BaseAudioContext.currentTime](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/currentTime). The context timeline is not a counter of samples heard, supporting the need to exclude scheduling gaps.
