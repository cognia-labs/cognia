## Problem frame

The initial audit compared O1 with ADR-0217 and reachable startup/connection paths. The authorized follow-up now moves reusable vendor behavior and portable lifecycle orchestration into the existing packages while retaining Host authority. Source movement must preserve behavior, package consumers, browser/Node separation and concurrent edits. Independent plugin delivery and authenticated provider acceptance remain separate work.

### Why this happened

ADR-0217 assigns registration, policy, PII, sandbox and persistence to the Host and explicitly retains the remote-host run plane and ACP MCP plumbing (lines 57, 298-340). Its “all six phases landed” status describes that scoped package migration; it does not promise the absence of app-side launch code.

Later development also added substantial vendor behavior outside those packages. Git history records the initial DSH/Codex extraction at `3f319be74f` on 2026-10-05 and the Hermes daemon module at `8e67646e6c` on 2026-10-27. The observation is explained by the original scope plus subsequent app-side growth, without assuming the package split was reverted.

### Recommended next boundary

1. Move reusable vendor connection/process strategies into integration packages, starting with Hermes coordination and ACP isolation selection. Keep credential access, state roots, sandbox enforcement, process authority and native bridge verification behind Host ports.
2. Separate the portable install/lifecycle core from `createDefaultLifecycleDependencies` and app bindings. Reuse existing contracts/package layers; justify any new package by its dependency boundary.
3. Let the manager consume typed connection/lifecycle strategies for timeout ownership, reconnect coordination and managed preparation, keeping Host authorization authoritative.
4. If optional installation or independent agent delivery is the desired outcome, design discovery/loading and artifact delivery explicitly. Moving source into `packages/` alone does not provide that.
5. Add a reverse boundary check for vendor implementation in app-private launch paths. Existing package checks primarily prevent packages importing the app; catalog checks do not prevent another vendor coordinator appearing inside it.

These were the recommendations at the initial audit snapshot. Their implemented scope and verification are recorded below.

## Authorized implementation — 2026-11-01 through 2026-11-02

Acceptance and verification sequence was fixed before implementation:

1. Move Hermes daemon coordination, ACP isolation selection and Hermes native helpers into packages; test package behavior and Host wiring separately. Baseline: 4 suites / 48 tests passed.
2. Replace manager vendor branches with package-authored runtime policies; retain plugin overrides, native retry ownership, connection serialization, write ceilings and DSH preparation for both SDK and ACP profiles.
3. Move portable lifecycle service, providers, receipts, credentials, catalog and version algorithms behind Host ports; retain keyring namespace, catalog data, native authority and refusal semantics.
4. Add reverse AST gates with rejecting fixtures; validate installed ESM/CJS/NodeNext consumers, browser closure, native staging, relevant tests, lint, types and build.

### Defects found by verification

- The Hermes Host facade initially captured a changing ownership callback through object spread; the wrapper now reads it live. Existing behavior tests cover the Host transition.
- Extracted ACP selection initially broadened Devin command matching to case-insensitive. A regression was reproduced, then fixed: Devin remains case-sensitive while MiniMax retains its existing case-insensitive executable matching. Custom/plugin subclasses stay authoritative.
- Installed CJS consumers initially saw two `JsonRpcMethodError` constructors because one entry inlined the class. Both peer and vendor profiles now share the public data-only error entry; installed ESM and CJS identity assertions pass.
- Fresh ACP builds initially resolved self imports through dist. The package now resolves its source self alias during typecheck while keeping the public registry import needed for singleton identity.
- OpenCode policy tests initially accessed an optional capability result directly. Typed structural assertions now check the same capability behavior and the package typecheck passes.
