## Problem frame

Audit and repair the existing non-TUI entry points against their owning contracts (G1,G2,C1,C2). Repair F1-F7/P1 first, then F8-F12/P2, preserve authority boundaries and concurrent edits, add behavioral regressions, build and exercise the current CLI against isolated fixtures, and reconcile independent adversarial review. Deployed/paired Host acceptance remains Q1; it is not inferred from generated enumeration or mock evidence.

## Authorized implementation follow-up — 2026-10-28

User request: 按报告把非 TUI CLI 的缺口逐项修复，先处理 P1，再补齐 P2，补上回归测试并验证，完成后再做一次对抗性审查，跨模型继续跳过。

Acceptance plan:

1. F1-F7: regression tests first for debug canary, per-wire schema, false/null, separate body/header idempotency, JSON result/Operation terminal states; canonical Rust operation fixtures; regenerate and check index.
2. F8-F11: complete per-plane schemas and local validation; executable approval remedy; raw/file/stream request modes and headers; machine-readable errors, Problem metadata, total deadline and cancellation.
3. F12: bounded pagination and event consumption with resume/reconnect; relay-only operation observation must be implemented through an authorized contract rather than silently use an unreachable HTTP route.
4. Run focused Jest and Rust tests, CLI type/lint/build and applicable contract gates, then source/built-artifact local flow checks. Complete independent adversarial review and reconcile; no cross-model review.

New-file constraint: only add modules when existing modules cannot coherently own the behavior. A shared global-flag data file prevents generator/runtime drift; an events client is separate from JSON RPC because it owns streaming connection and cursor lifecycles. Both require regression coverage.
