## Problem frame

Audit the current checkout, treating terminal support as the integrated interactive terminal plus SSH/serial, paired-host access, agent/workflow execution and extension entry points (G1). Trace entry points through transports and native handlers, then run focused existing tests. Distinguish implementation, deterministic verification and real-environment acceptance. Do not infer deployment or device behavior from documentation or mocks (O2, O3). Preserve concurrent work (O1, C1).

## Initial findings and follow-up order

1. **Interactive result semantics need attention.** `runInDockTab` and Dock wait_for_exit return `output: last?.cmd`, and the interactive workflow forwards that field. For a command producing `hello`, this source path supplies the command line instead of its stdout. The separate `command-output.ts` helper reads xterm buffer rows for UI output actions; it is not used by these return paths. Headless execution has a different implementation returning backend output. Before changing anything, define whether the interactive API promises stdout, terminal output, or command metadata, then add a discriminating behavioral test. Also account for shells without integration, which cannot signal command_end normally.
