## Original request

> 帮我分析一下现在的权限管理和空间管理，看看差什么功能，或者存在什么问题，并且对照业内的优秀实践

## 结论

Cognia 已有组织与空间两级角色、访客、邀请、成员变更、所有权移交、权限摘要和审计事件。最大缺口在管理流程：**本地工作区能创建和归档，组织共享空间仍缺自助生命周期**。个人工作区里，归档后的空间仍可被调度解析，移除失败也可能已经迁走数据。团队治理最缺的入口是组织级人员目录，以及能够按人、空间和时间追溯变更的审计界面。

本次以 2026-11-19 的本地工作树为对象，HEAD 为 `4467048e73a09cb3da03aba8d75cf0ea4085ea45`。通过源码调用链、合成数据探针、既有测试和官方文档交叉核对。排序优先考虑数据状态误判、后台执行和日常治理。共享空间相关的 P1 以 Cognia 要支持团队自助协作为前提。

### 团队规模或合规要求出现后再做的能力

- **空间发现和加入策略。** 可先支持“目录可见、需要邀请或申请”与“仅成员可见”，分别定义名称是否公开、谁可申请、谁可审批和谁能看内容。组织成员默认无空间访问以及 owner/admin 继承管理权，都是现有明确契约。若需要连管理员都默认看不到内容，必须先确定救援和审计政策。
- **组授权、自定义角色及企业身份管理。** 先验证批量入组、暂时停用、离职交接是否形成重复操作。按需求引入组织组、组到空间映射、受限的动作预设或 SCIM。现有固定角色与动作矩阵可继续承载小团队。
- **跨资源授权的策略验收。** 共享会话已有单独角色、面向个人的邀请、文件共享政策和恢复入口。扩充文件、会话、连接凭据与 Agent 执行之前，先用正负矩阵确认资源、动作及发起主体，并记录撤销时效。见 [协作实施契约](../../crates/cognia-collab-server/ENFORCEMENT.md)。

## 推进顺序

1. **先修已有行为。** 将归档语义和后台准入对齐，修复移除失败后的部分完成。两个问题已经可以在本地复核，个人模式和组队模式都受益。
2. **再做共享空间自助管理。** 复用组织身份、服务端角色与工作区镜像。最小闭环是组织管理员创建空间、成员可发现或受邀进入、改名、归档/恢复、退出及回收。同步做组织人员目录和按空间筛选审计。
3. **最后扩展治理粒度。** 根据团队场景加入定向/限期访客、组授权、空间发现规则和跨主体的权限解释。大型组织才需要的身份系统对接和自定义角色可单独排期。

## Problem frame

G1 覆盖个人工作区、组织共享工作区，以及影响二者的目录信任、设备授权与 Agent 执行授权。以普通管理动作能否从入口完成、状态何时生效、故障后是否一致为核对点。空间指 Cognia Workspace。审计为只读，探针只使用临时合成数据。
