# ADR-0246 ES-32 built-in migrations

Date: 2026-11-02. Built-ins remain Host contributors. The consumer column names
runtime owners, not newly packaged plugins. Plugin consumers use the same public
contribution contracts with their own consumer grants; built-ins use Host drivers.
The format follows the behavior/status/evidence discipline of
`plugins/feishu-calendar/README.md`'s ES-32 behavior table. Evidence below names
behavioral assertions, not tool registrations.

## Verification boundary

The final fixes verification ran the requested Jest groups: 159 suites, 1936 tests
passed and Jest exited normally. The focused shared-dialog and backup-card rerun
also passed 23 tests; the final backup-card-only check passed all 13 tests.
The scoped TypeScript check (15 changed files plus the unchanged Lark Host driver),
ESLint, Prettier, i18n aggregate parity and i18n lint passed.
The single-crate Google command compiled and ran: 23 passed, 13 failed at
mock-server socket binding, including the two collision tests. The corrupt-record
and empty-record migration regressions passed. Native HTTP fixtures require
loopback socket binding; the Codex sandbox refuses it with `Operation not permitted`. These tests remain in
place for the orchestrator's outside-sandbox rerun. No live Google sign-in,
revocation, desktop UI, or headless provider acceptance is claimed by a fixture.

Headless routing is present in source: `cli/src/serve/serve-command.ts` installs a
`CompanionTransport` using `/internal/_rpc` with `setTransport`; the Google state
invoker reads the live `transport` binding. Connector command wrappers also have
their own invoker seam; Drive token acquisition uses the state transport, not a
renderer OAuth fallback. Companion generated artifacts are intentionally left to
the orchestrator's isolated regeneration.
