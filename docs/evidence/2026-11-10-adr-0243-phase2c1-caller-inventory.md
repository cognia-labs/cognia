## Verification boundary and remaining phases

Focused tests and TypeScript/source guards establish local behavior. They do not establish live provider, collab-server or native desktop acceptance. The final task report records the actual command results.

D1's legacy read-time connector attribution still filters history but does not itself taint a consuming run. Public snapshots retain that strict legacy attribution. Phase 2C-2 owns opaque egress, and phase 2D owns person-authorized exact-content/target disclosure. An absent content hash means not disclosable; no current operator or confirmation overrides a withhold. Existing phase 2B-2 native/paired-owner work remains outside this slice.

## Owner-only local premise and evidence location

Phase 2A-0 admits personal credentials for the Host owner only. Unknown provenance therefore does not redact owner-local UI; a known foreign-person mark still does. Revisit this premise when phases 4/5 admit other people's personal credentials. Paired member-device delivery remains phase 2B-2 and is not equivalent to Host-local display.

This evidence file is outside the Fumadocs content collection. The requested `docs/evidence/` destination is outside this task's path allowlist, so it is kept beside the Host sink implementation under `lib/execution/` without widening the edit scope.

Issue confirmation replay retains a separate Host-only `issueProposalSource` sentinel in existing callback storage (not component/model payload). Before creating an issue, the callback matches the exact draft/project/conversation and rechecks live provenance; missing legacy proof withholds. Failover/load-balance preserves session/composite source context and original narrowing metadata. Derived branch/attached sessions follow canonical source-session ancestry with cycle/depth protection.
