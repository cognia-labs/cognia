## Problem frame

Assess the current `/inbox` experience (G1), distinguishing concrete failures from deliberate constraints and optional product expansion. Follow the flow from incoming platform message to triage, draft/manual reply, durable relay, outbound job and visible result, including concurrent lifecycle changes. Success is a reproducible, prioritized assessment, not a claim that Inbox has been fixed. Broader notification-center consolidation, an email client, multi-user support staffing, automatic AI admission and product implementation are outside the authorized change scope (C1).

## Capability map and important boundaries

- **Already present:** desktop resizable three-pane layout, tablet preview, mobile open/swipe/long-press/bulk selection, keyboard triage, URL-held grouping/filter/preview, retryable error states, unread/pin/archive/resolve/snooze, character/Agent-team/human takeover, labels, contact identity merge, activity trail, canned responses, pending-draft approval, SLA badges/escalation and adapter-health/recovery notices. Owners: `components/inbox/`, `components/mobile/inbox/`, `hooks/inbox/`, `lib/inbox/`, connector runtime and overrides.
- **Existing durable seams:** manual text/attachments and draft decisions use `lib/connectors/inbox-writes/`; remote actions use a durable queue; delivery has persisted dedupe and an explicit `delivery_unknown` lane for ambiguous non-idempotent sends. Personal provenance and governed outbound authorization are already present. This report does not recommend rebuilding them.
- **Global message search exists:** `lib/global-search/providers/messages.ts:52-98` maps full-text message hits into IM conversations. Inbox-local search only checks title/key/recent preview. The opportunity is contextual filtering and discoverability, not another full-text engine.
- **Deliberate constraints:** standalone unpaired browser/phone needs a Host; preview does not mark read or suppress notifications; inbound admission remains rule-based (ADR-0131). Human assignment is a single-user takeover marker, while `team` refers to an Agent Team. These are not defects.
- **Notification center is separate:** ADR-0042 owns general notifications. Comparing Linear's notification Inbox to this IM workbench is useful for attention management, not proof that every Linear notification feature belongs in `/inbox`.

## Recommended order and acceptance

1. **Repair trust in actions:** F12 conflicting draft decisions and F13 editor identity/content first; F08 + F04 remote acceptance/convergence; F03 + F01 approval-to-delivery integrity; F02 expiry; F05 Host assignment compatibility; F11 truthful delivery copy. Existing governance and ambiguous-send handling must survive.
2. **Protect follow-up state:** F14 skipped-delta reconciliation; F06/F07/F10 transaction/version guards and F09 badge membership. Acceptance: adversarial interleavings preserve newer work, audit trails match data, and each badge leads to reachable conversations.
3. **Protect accessible controls:** F15 collapsed notice focus, preserving open portal state.
4. **Make attention actionable:** G01 saved views and G04 waiting/follow-up semantics, then G02 contextual search. Measure time to find and complete representative work; avoid using unread alone as the work backlog.
5. **Improve supervision and efficiency:** G06 structured handover and stale-context review, then validate G03 inline reply. Add G07 metrics to judge outcomes rather than feature count.
6. **Expand conditionally:** G05 multi-human collaboration only after Q1; G08 performance work after measurements, and real-shell/provider qualification before support claims.
