## Problem frame

用户应当能回答今天/本月消耗了多少、这笔钱对应哪个项目或 run、多少钱已确认、多少钱仅是估算、哪些调用受预算约束。当前主要问题是同一用量在采集、成本结算和使用端可能变成不同数字（O1–O3）。阶段验收应从相同样本跨接口对齐开始，随后验证真实账单、真实 Host 和移动端（Q1）。

## 结论

Cognia 的消费可见性已有较完整的产品形态。此时最该投入的是**单次调用只入账一次、硬预算原子占额、跨端更正可重放**。2026-11-20 已复现 Gateway 双入账、同一次审批放行两笔、Fusion 投影交接期可再次占额，以及配对更正和删除遗漏。报表里显示的钱可能是 SDK 估值、本地价格推算、Router + Fusion 保守入账，也可能混入其他工具折算出的价格。每种金额都能回答有价值的问题，但需要标清来源、到哪一步已确认，以及哪些数据尚未覆盖。当前有低报和高报两种方向，无法用一个全局修正系数解决。
