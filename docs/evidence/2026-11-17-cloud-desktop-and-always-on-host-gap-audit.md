## Problem frame

以 2026-11-17 本机 macOS arm64 的 `dev` 工作树（HEAD `5aa7d48ead`，含已有未提交变更）为样本。核对用户能否从正式安装包创建受管桌面、用配对设备稳定观察或接管，由 Agent 验收并回收；同时核对常驻 Host 在客户端离线、设备撤销、升级、重启和网络分区时能否维持正确的执行状态。发布制品和线上部署状态需要单独回读。本轮交付为分析和可复验证据。

三个入口共用部分 Host 基础设施。**托管云电脑**是现有 Host 创建和管理的 E2B Linux 桌面，现有策略面向限时、隔离的人工或 Agent 验收。**外部远程桌面**通过自备 VNC 或提供方连接能力访问已有机器。**常驻 Host**是自备 Linux/Mac 等机器运行的 Cognia server + brain，负责 Bot、定时任务、连接器和远程执行。云桌面的 E2B 计算发生在云端，资格、授权、对账、验收和查看器代理仍依赖所选 Host。关掉客户端、Host 停机和云 VM 到期是三个独立故障场景。

## 建议推进顺序

1. **发布及安全门槛。** 云电脑验证声明启用的构件含 Recipe 8 pin 和有效回执。外部 VNC 假上游与真实上游均拒绝 View 输入。常驻 Host 用两个进程验证撤销生效后旧通道收到零新事件，用旧库样本验证升级不会隐藏历史。
2. **恢复及数据一致性。** 云电脑从安装包创建、观看、接管、关页重进验收、停止及销毁。用供应商读回验证任务资源清零，并注入 envd、证据、凭据故障和传输中断。常驻 Host 演练无人登录开机、已有数据通道并发写、Sidecar 启动失败、备份恢复和双 Worker 分区。记录恢复耗时、恢复到的数据时点和外部动作次数。
3. **按用户场景扩展。** 临时验收优先支持限定出网、短期凭据、跨端继续、证据下载和可诊断的连接。长期办公再定义存储保留、闲置暂停、恢复点、区域、多桌面和持续费用。常驻 Host 按任务隔离执行，并在设备页显示可达性、就绪态、可用能力及恢复状态。

## 2026-11-17 跨环境复核

首轮的“默认构建休眠”仅适用于没有有效清单的 Host。跨端能力与制品启用条件分别核对如下。

| 环境                           | 实现状态                                                                                            | 尚缺或受限项                                                                                                                                                            |
| ------------------------------ | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| macOS、Windows、Linux 桌面 App | Tauri 本地 Host 或已配对远程 Host。同一功能由客户端将管理与 I/O 路由到指定 Host。                   | 默认仓库资源缺 pin，特定 Host 的数据目录清单和资格仍需读回。Windows Host 的 Git 验收交接另有平台限制。                                                                  |

## 预装镜像支持评估

2026-11-17 用户追问“云电脑应该提供预装镜像支持吗”。建议作为跨端云电脑的基础产品能力，先交付默认标准镜像和创建时的软件清单展示，再按使用场景扩展可选镜像及项目预构建。该建议尚待用户决定范围。

现有基础已包含 Debian、Chromium、Openbox、终端、Python、Git、Node/npm、字体、剪贴板组件及 Cognia Guest 控制程序。Host 会把可信 OCI 镜像转换为用户 E2B 账户中的模板并复用。当前 Host 持有单一 `trusted_release`，配置必须完全匹配。模板页面提供状态、在用数量及删除，尚缺按用途选择镜像、软件版本清单、自定义构建和项目预构建的产品入口。 [基础镜像](../../crates/cognia-automation/src/cua_sandbox/image/Dockerfile#L20) · [单一可信版本](../../crates/cognia-automation/src/cua_sandbox/managed/service.rs#L298) · [模板页面](../../components/settings/automation/managed-desktop-templates.tsx#L19)

建议将系统与常用软件作为可复用镜像，把项目依赖与初始化结果作为绑定仓库提交的预构建，账号和实例凭据在创建时按权限注入。镜像目录记录不可变 digest、软件版本、适用 provider/架构、Cognia 协议资格、维护日期和停用状态。桌面/Web/移动端从同一个 Host 目录读取兼容项，Host 校验所选版本并复用匹配的 provider 模板。

业内参考包括 WorkSpaces 的自定义镜像与硬件 bundle，以及 Codespaces 按仓库、分支和 devcontainer 配置生成预构建。Cognia 可以据此实现“选预装环境 → 选规格与期限 → 创建并使用”，同时记录构建耗时、缓存命中率、启动就绪耗时和实际任务成功率。 [WorkSpaces 自定义镜像](https://docs.aws.amazon.com/workspaces/latest/adminguide/create-custom-bundle.html) · [Codespaces 预构建](https://docs.github.com/en/codespaces/prebuilding-your-codespaces/about-github-codespaces-prebuilds)
