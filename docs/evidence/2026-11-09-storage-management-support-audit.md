## Problem frame

Trace meters, manual cleanup, retention and recovery to the stores that own the bytes (O1, O2). Compare what the entry points tell users with what is read, deleted or reported when a store fails. The audit covers the Tauri Settings surface, the headless Host (Rust front door and Node brain), and the CLI surfaces operators might use (G1, C1).

## Adversarial review disposition

The re-audit at `bc08caccfd` retained the original eight finding groups with these scope corrections:

- Native SQLite reuses freed internal pages. The missing operator path to shrink the main file is a capacity-management gap. Orphan side files and an unobserved busy WAL checkpoint are separate behaviors.
- The desktop's typed “Everything” choice says “entire database”. It is a reset of the selected DB and related data. Deletion of the main DB and Router/Fusion DB is verified. The problem is the unconditional success UI after a failed ancillary cleanup.
- Messages cleanup immediately hides Files-only uploads by removing their ownership references. The probe confirmed that the blob still existed at that point. Subsequent collection depends on the remaining references and a GC trigger.
- The TUI `/doctor` intentionally measures CLI home, and Rust `cognia host doctor` is an endpoint/configuration diagnostic. The absent Host-volume capacity view is a support gap. The unsafe cleanup advice generated for the TUI's current working directory is a separate defect.
- `/healthz` reports runtime startup status. It lacks per-sweep outcomes. The data-only member profile lacks the brain retention initializer by design of the current registration, which is a coverage boundary. Long-term member-volume growth is unmeasured.
- The earlier Jest mismatch on unpinned journal discovery is a stale test expectation. The independently reproduced unpinned SQLite migration is a separate production failure.

Evidence labels below distinguish a **Probe** using the owning code, a **Source** conclusion, and a **Gap** in supported operations. The priority is this audit's triage. Several related symptoms share one row.
