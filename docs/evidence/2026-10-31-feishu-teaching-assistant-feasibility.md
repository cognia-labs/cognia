- Status: verifying

## Verdict

现有 plugin、Bot、Agent 和 connector 体系能够承载授课助手，但当前没有开箱可用的授课场景实现，不能只配置一个通用 Bot 就宣称完整跑通。建议使用一个授课插件承载业务状态、一个明确绑定学校应用的 connector 接收消息，以及一个负责材料分析的 Review Agent。

| 功能                               | 可复用的基础                                                         | 仍需补齐                                                                       |
| ---------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 话题内文档 Review、追问与复审      | 同话题会话和回复；文档读取、原文定位、指定版本、写入工具；Agent 执行 | 可用的学校文档身份通道、每话题绑定、Review 问题与版本记录、完整报告交付        |
| 自愿邀请搭档、接受或婉拒、现场交接 | Lark 卡片与验签回调、Bot 持久任务、事件等待与超时                    | 邀请对象本人确认、原子状态转移、去重、无响应分支、具体现场分工                 |
| 知识要点、前置基础与参考资料       | 文档解析、知识检索、来源与版本定位、Agent 生成                       | 来源核验、讲师批准状态、新资料的访问权限传播；原格式图片或画板处理按需新增操作 |
| 可选提醒与实际借还                 | Scheduler、Bot timed triggers、插件持久存储                          | 用户偏好、实际借用记录、停止条件与常驻执行 Host                                |

分工应保持简单：connector 负责平台传输，Bot handler 负责持久业务流程，Agent 负责内容分析，插件保存课程、文档版本、问题、协助约定与发布状态。不能让模型自行决定某位讲师已经同意到场，或用聊天记忆替代业务记录。

## CLI 1.0.98 repair (2026-10-31)

用户在初始审计后授权修复 CLI 兼容性、凭据传递和账号选择。本节是修复后的结论；下方保留初始失败证据用于对照。

- 将严格认证版本更新为 **1.0.98**，继续检查全部 43 个工具需要的命令和 flag；旧版或缺少能力仍会被拒绝。
- 使用该版本实际读取的 `LARKSUITE_CLI_*` 变量传递所选 Cognia 连接的应用凭据及单一身份 token，清空继承的另一种身份 token、profile、认证代理和 token 来源选择。凭据仅传给子进程，不修改用户 CLI 登录或配置。
- 43 个工具统一支持可选 `adapterId`：飞书会话使用数据库根会话绑定；本地会话可明确选连接，未选择时只允许唯一启用连接。多账号歧义、跨账号、禁用连接、非飞书连接和失效绑定均报错。
- 写操作确认前固定连接，并在确认卡上展示名称及 ID；持久化参数携带该 ID，确认后重新检查绑定。默认连接变化不能改变已确认操作的目标。CLI `--profile` 或冲突的 `--as` 无法覆盖选择，文档正文中的同名文本仍作为数据保留。
- 首次构建工具清单先等待能力探针，缓存键包含探针结果；非飞书会话及仅 Scheduler 的场景不触发无关探针。
- 真实本机 CLI 使用虚拟凭据、关闭网络出口，验证 user/bot 身份及干扰环境隔离，并检查全部 43 个工具的 dry-run 合同。源码安全复核和 PII 复核均无阻塞发现，13 个改动源文件均有同位置测试。

外部 `school-club` CLI profile 和 Cognia connector 是两个独立配置入口。本修复复用 Cognia 已有连接及 keyring，不自动导入或迁移外部登录。此修复阶段未验证真实学校读写；随后外部 CLI 的真实结果见下一节。Cognia 实际桌面二进制、学校 connector 凭据桥接、租户 ACL 与 token 刷新仍未验收；内置进程桥限定 Tauri。全仓类型、lint、static-export 检查中的范围外失败见 V9 / X6。

## Live school document verification (2026-10-31)

**学校外部 CLI 的真实读写已通过；Cognia 凭据桥接的真实验收仍被阻塞。** 用户确认目前只配置了 CLI 的 `school-club`，没有在 Cognia 配置学校 connector，因此本轮不能把外部 CLI 成功当作 Cognia 账号选择 / keyring / 环境注入链路的成功。

- 使用真实 `lark-cli 1.0.98 --profile school-club --as user`，`auth status --verify` 服务端校验成功。仅创建一份独立测试文档：[Cognia 学校飞书读写验证 2026-10-31](https://njupt-sast.feishu.cn/docx/ZOoOdmJmjoq0UzxqsYXcIjBunH3)。未修改原有授课文档、共享权限或其他账号的资源。
- 创建后读取初始唯一标记，再追加更新标记并读回；版本从 **3 → 4**，两次标记均匹配，所有文档操作返回 `identity=user`。学校应用为 `cli_aa6e…dd00`，用户 openId 为 `ou_a2ee…ae08`。
- 服务端 `drive metas batch_query --user-id-type open_id` 返回的 `owner_id` 和 `latest_modify_user` 均与该学校用户完整 openId 相同。文档位于 `njupt-sast.feishu.cn`。
- 本机默认 CLI 对应另一个应用。将继承的 `LARKSUITE_CLI_PROFILE` 故意设为该已配置的其他 profile，再显式指定 `school-club`，whoami 仍匹配学校应用及用户，新文档读回仍匹配更新标记。该结果证明本次显式 profile 调用没有改投默认应用；不是对任意环境或 Cognia 尚未配置的连接作保证。
- 使用标准 `pnpm tauri:debug:agent --no-watch` 启动当前源码，前置构建在 `Host authoring kit ABI ... mismatch` 处失败，未得到真实 webview / native credential bridge。没有绕过契约校验、改写并发中的 authoring-kit pin 或导入 / 覆盖 CLI 凭据。

首个创建探针误加普通 `docs +create` 不接受的 `--yes`，CLI 在参数校验阶段退出2、未发起创建；仅在确认该拒绝后去掉参数重试一次。Cognia 文档工具自身已经只向高风险命令添加此参数，因此无需改动其生产代码。测试文档保留供复核。

## Problem frame

Assess whether the simplified teaching workflows fit current extension points (G1), then repair the confirmed desktop CLI compatibility boundary under the subsequent authorization (G2). Scoped existing-module changes, deterministic regressions, local native CLI probes and independent reviews are in scope. The later G3 authorizes real reads/writes on one new school test document; actual Cognia bridge acceptance is retained as V11 / X7. Building the teaching plugin, adding a headless transport, publishing messages and declaring live school acceptance remain outside this repair (C1). H1 is refuted; H2 remains the proposed scenario route pending implementation and live acceptance.

## Concrete implementation boundaries

External `school-club` CLI profile is not the Cognia adapter binding.
- **CLI and Host (after repair):** `capabilities.ts` certifies exactly1.0.98 and all required flags; `auth-bridge.ts` emits isolated `LARKSUITE_CLI_*` credentials; `exec-lark-cli.ts` enforces the chosen identity. `process.ts` still runs through Tauri. Dummy native whoami/dry-run success does not establish actual GUI or school API success.
- **Public plugin path:** `ctx.agent.invokeTool` does not allow arbitrary built-in Lark calls (`packages/plugin-contract/src/types/plugin/plugin-host-tools.ts:43`). Register a provider/actions through `ctx.auth.registerProvider` and manifest integrations; use structured `ctx.integrations.executeAction` for Bot-bound actions (`lib/plugin/api/bot-integration-binding.ts:143`). `lib/integrations/action-runner.ts:210` and `:695` inject scoped authenticated requests without a Tauri-only branch. A new Lark provider/action contribution is still required.
- **Storage and consent:** `ctx.storage` has a 5MB limit (`lib/plugin/api/storage-api.ts:43`); scoped plugin Dexie tables and transactions are the appropriate state surface (`lib/plugin/api/dexie-api.ts:14`). `lib/bot/runtime/step.ts:405` returns null on wait timeout. Callback actor checks and deterministic invitation transitions must remain separate from generic operator approval (`lib/connectors/callback-authorization.ts:269`).
- **Knowledge and publication:** `lib/skills/built-in/lark/doc.ts:259` supports native doc location/version reads; `lib/claude/knowledge-builtin-tools.ts:15` exposes knowledge reads. Raw-text ingestion (`lib/twin/ingest/lark-doc-fetcher.ts:244`) does not preserve native block/image/revision fidelity.
