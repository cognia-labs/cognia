## Workflow usage snapshots

A concurrent, uncommitted change in the main tree (2026-11-12) makes a step attempt's `step_usage` reports cumulative snapshots keyed by `stepExecutionId`, with `costKnown: false` for incomplete aggregates. The person chose to keep that semantics. The live budget no longer reads `step_usage` (the ledger meters each model call), so the rule applies where the reports are still summed: `summarizeRunBudget` takes the latest snapshot per `(stepId, stepExecutionId)`, adds reports without one, and counts `costKnown: false` as unknown. It reads the payload fields directly so this change does not depend on the uncommitted `stepUsageKey`. Pinned by `budget-summary.test.ts` "counts an attempt's cumulative snapshots once, and keeps attempts apart".

## Residuals

- Embedding calls (`knowledge.embed`, `twin.rag`) reserve nothing.
- External engines on their own login are metered only by what they report until 3B-2 forces gateway-capable engines onto the gateway.
- A cross-project sub-workflow starts as an observed root and draws on its own declaration, not its parent's tree.
- Boot recovery settles every hold no live process claims. The ownership claim is per process, so a headless brain and a window that share one database could settle each other's live holds.
