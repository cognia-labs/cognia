# Integrated Terminal

<Status variant="stable">Stable · ADR-0031 → 0033</Status>

<TLDR>
  The terminal is a real PTY, not an emulator over a command runner. On the desktop the PTY is owned by
  the **durable terminal host** (`crates/cognia-terminal/src/host.rs`), which outlives a renderer reload:
  the dock reattaches on boot and closing a tab detaches by default. The transport is chosen by
  `selectTerminalTransportChain()` (`lib/terminal/pick-transport.ts:63`): `tauri-channel` on a plain desktop,
  and `ws` then `webrtc` for Capacitor mobile, a browser paired to a Cognia server, and a desktop driving a
  remote Host. Prompt boundaries, exit codes and cwd changes come from **OSC 633** shell-integration sequences
  parsed in Rust (`crates/cognia-terminal/src/osc633.rs`), which validates a per-spawn nonce so a hostile
  process inside the terminal can't fabricate prompt decorations. Agents and workflows use the visible dock
  behind a per-tab trust gate (`lib/terminal/agent-trust.ts`), or a separate headless surface.
</TLDR>

## Transport selection

```ts
type TerminalTransportKind = "tauri-channel" | "ws" | "webrtc" | "unsupported"
```

Two entry points, deliberately separate. `selectTerminalTransport()` returns the single highest-priority
transport for callers that don't want fallback logic. `selectTerminalTransportChain()` returns an ordered
list the spawn orchestrator walks, trying the next transport when the previous one returned `null` or threw.

| Shell | Chain | Notes |
| --- | --- | --- |
| Tauri desktop | `tauri-channel` | local IPC to the durable host on this machine |
| Desktop → remote Host | `ws`, `webrtc` | the Host's `/ws/terminal` ([ADR-0082](../adr/0082-remote-development-remote-host)); inert until a remote Host is selected, so a plain desktop is unaffected |
| Capacitor mobile | `ws`, `webrtc` | LAN / mDNS first, then the WAN data channel |
| Browser paired to a Cognia server | `ws`, `webrtc` | runs on that server's headless host |
| Standalone browser | `unsupported` | the chain returns `[]` and the dock does not mount |

The `webrtc` leg rides the ordered `cognia.terminal` data channel, which the Host routes into the same
terminal frames the WebSocket carries. A phone or browser never runs a local shell: it needs a reachable,
paired Host and a terminal grant. `terminalAvailable()` (`lib/terminal/pick-transport.ts:76`) is what
components use to decide whether to mount the dock at all.

### What the Host says about itself

A remote Host reports its platform, default shell and available shells in the hello ack and the session
list (`crates/cognia-terminal/src/host_capabilities.rs`), along with the protocol features it speaks. The
renderer caches that answer in `lib/terminal/host-capabilities.ts` **per selected Host**: switching the
Host a desktop drives, or returning to the desktop's own PTY, invalidates it, and an answer that arrives
for a Host no longer selected is dropped. With no project or user shell set, a new tab — on the desktop
dock and on the phone alike — spawns the Host's default shell rather than one guessed from the client's
user agent.

## Shell integration is nonce-validated

VS Code's `ESC ] 633 ; <C> ; <args> BEL` family is what turns a dumb byte stream into a structured session:
prompt boundaries, command pre/post-exec, and cwd changes. PTY output streams through
`Osc633Parser::feed`, which yields the raw bytes back **unchanged** — the terminal still needs them in
scrollback for fonts and colours — and separately surfaces a typed `IntegrationEvent` when a complete
sequence is recognised.

The security property is the per-spawn nonce stamped into `$COGNIA_TERM_NONCE`. The parser validates it, so
a hostile process running *inside* the terminal cannot emit its own OSC 633 sequences to fake prompt
decorations. Unrecognised sequences are dropped rather than guessed at.

## The durable host

`host.rs` owns the PTYs, their attachment queues, replay buffers and the single controller lease. The
desktop's native commands are a facade onto it (`src-tauri/src/terminal_host_bridge.rs` re-exports the
crate bridge), so a webview reload or a closed tab does not end the shell: boot reattaches what is still
running, and the tab's close button detaches unless you choose **Terminate**. Durable means surviving the
renderer, not the host process or a reboot. Replay is bounded: 8 MiB per session, 128 MiB in total,
32 sessions, 8 remote sessions per device.

## Sharing a session with a paired device

A hosted session can be watched — or driven — from a paired phone or another Cognia
([ADR-0133](../adr/0133-terminal-session-sharing)). There is no share link and no second transport:
the device attaches to the same durable host over the companion `ws`/WebRTC adapters and takes part
in the host's **controller lease** — one controller at a time, everyone else read-only, "Take
control" / "Release control" from the session chip. The dock's **Share** button (desktop host only)
opens a dialog with the host's live participant roster and a switch per paired device for its
remote-terminal grant; the grant is device-wide (every terminal on the host), and removing it drops a
live attachment within a second because the adapters recheck it continuously. The host re-broadcasts
the session snapshot whenever a client attaches, detaches, or the lease moves, so the chip
("Shared with N devices") and the dialog update without polling. `lib/terminal/collaboration/roster.ts`
is the pure renderer-side projection of that roster.

## Agents don't get a free shell

An agent reaching the terminal passes two gates. `headless-exec.ts` is a separate, non-interactive surface
with its own registry (`headless-session-registry.ts`), so an agent run never silently inherits an
interactive tab. To drive an *interactive* tab it must first clear `requestAgentTrust()`
(`lib/terminal/agent-trust.ts:50`), which is keyed per chat session **and** per tab —
`agentTrustPluginId(chatSessionId, tabId)` — so trust granted in one tab does not leak into another.
`isAgentTrusted()` is the read side of that gate.

### What a driven tab reports

`runInDockTab` (the `terminal_dock_spawn` / `terminal_dock_write` tools and the interactive workflow
nodes) writes the command, waits for its OSC 633 `command_end`, and returns the exit code plus the text the
command printed: the stream between its `C` and `D` sequences with control sequences stripped, the same
shape the headless runner returns. `terminal_dock_wait_for_exit` waits for whatever is already running, so
its `output` is only what was printed while it waited, and its `command` field carries the command line.
Very long output keeps its tail and sets `outputTruncated`. A shell without integration (cmd, or an
unknown shell) never reports `command_end`, so these calls time out there.

### Workflow sessions

`action.terminal.session.open` registers what it opens with the run, and the run's end closes whatever is
left. A cancellation that lands while the open is still waiting for its spawn is honoured: the late
session is closed rather than registered into a run that has already cleaned up.

## Serial ports

The dock can open a native serial port on the desktop (`serial-session.ts`, `crates/cognia-terminal/src/serial.rs`).
A port can only be opened while the desktop drives its own PTY (the chain starts with `tauri-channel`).
It is always the desktop's own device, so an open port keeps reading and writing locally if a remote Host
is selected afterwards. A serial port has no host-side owner to come back to, so it is not reattachable:
closing its tab closes the port, and the dock does not offer "detach" for it. Serial is not exposed over
the paired terminal path.

## Known limits

- **Unattended execution is local on the desktop.** The headless commands (`terminal_headless_exec`,
  `terminal_headless_run`, `terminal_headless_spawn`) are client-local, so a Tauri desktop runs unattended
  workflow commands on itself even when a remote Host is selected in the UI. Paired and headless clients
  route one-shot runs to their Host through `terminal_exec`, which rejects a persistent session, a requested
  sandbox and a custom shell.
- **Recording is a library, not a feature.** `lib/terminal/recording/` holds an asciicast v2 recorder and
  player with unit tests, but no surface records or replays a terminal yet.
- **Verification.** The terminal module's real-shell smoke is still pending; SSH, serial hardware, WAN and
  Windows/Linux shells have not been accepted end to end.
