# ADR 0255 — 共用目录的运行保留 diff，放弃撤销

**状态：** 提议中
**日期：** 2026-11-11

**相关：**
- [ADR-0086](./0086-task-scoped-resource-workspaces)：TaskRun 与 PatchSet，本 ADR 约束的采集。
- [ADR-0111](./0111-managed-workspace-registry-and-bundle)：托管根仍是隔离 agent 的默认方式，不变。
- [ADR-0227](./0227-agent-changes-integrate-through-one-host-queue)：变更集与集成队列，不变。
- [ADR-0244](./0244-a-remote-run-has-stopped-only-when-its-worker-says-so)：远程 worker 的停止证明，不变；本 ADR 处理没有这种证明的应用内运行。

**依据：** 方案 `docs/plans/2026-11-11-change-lifecycle-stopgap-and-history.md` 第 2 节（2026-11-10 与 2026-11-11 核对的源码事实）及第 4、6 节。它取代 `docs/plans/2026-11-10-change-lifecycle-convergence.md`，后者的 W02 提议对物理根做独占预留。

## 背景

一轮的 diff 是目录在开始和结算两个时刻的差。撤销是把这份差合并回去。

- **diff 覆盖整个目录。** 结算时拿所有被跟踪的路径和基线比，不按本次运行碰过哪些路径过滤。
- **没有任何记录说明文件是谁写的。** 内置写文件工具和 Claude SDK 路径都不向宿主上报运行级的写入。唯一的工具时刻命令只带路径、不带哈希，而且只有 Codex 和 SIWC 适配器在调用。带哈希的回执通道存在，但没有生产调用方。
- **现在第二个运行会被拒绝。** 一个运行就地观察某个目录时，在该目录或它的父子目录上再开一个就地运行，会在开始时失败。
- **实际上大家就是在共用目录。** 父 agent 和它的子 agent、同一个仓库上的两个聊天会话、没有隔离工作树的小队队友、Cognia 之外的编辑器和其他 CLI agent，都会同时写同一个目录。

两个运行同时活动时，每个运行的 diff 都含有对方的改动，撤销其中一个就会抹掉另一个做的事。之前的方案用每个物理根一份持久预留、参与者注册和固定锁顺序来解决，它靠禁止共用来保证归因准确，而共用正是用户依赖的用法。

旁边还有一个缺口。取消或超时之后，应用内的执行器可能还在写。ADR-0244 给了远程 worker 停止证明，应用内运行没有；如果等到证明才放开目录，一次超时就会锁住用户的仓库。

## 决定

### 1. 允许共用目录

目录已有运行在观察时，另一个运行可以在上面开始，开始阶段不再因此拒绝。要准确归因仍然用托管根，这里不改动它。

与「停止未确认的远程运行」相交的目录，现有的拒绝保留（ADR-0244）。

### 2. 重叠使这一轮只读

两个运行都处于运行中或结算中，并且它们的目录相同或互为父子，就是**重叠**。宿主在三个时刻发现重叠并打标记：开始时；Apply 或 Undo 写入一个有活动运行的目录时；以及放行一个不带采集的执行器进入该目录时。标记存在运行上，只加不减。

带标记的运行结算出的 patch 不可逆，原因是 `overlap`。diff 照常可读，基于这个 patch 的撤销和快照恢复被拒绝，并显示原因。

同一轮里的父 agent 和子 agent 共用一次采集，不算重叠。

Cognia 之外的写入者看不到。撤销本来就做三方合并，合并不了时报冲突，这仍是对它们唯一的保护。

### 3. 停止未证实使它自己那一轮只读

应用内执行器被取消或超时后，在限定时间内等不到完成信号的，这一轮仍然结算以保留 diff，但 patch 不可逆，原因是 `stop_unproven`。目录不被扣住：下一轮可以在同一目录开始，基线取当时的磁盘状态。

远程 worker 运行继续走 ADR-0244 的确认流程。

### 4. 只有整目录恢复需要独占

恢复快照会替换目录里的全部内容。它只在该目录及其父子目录上没有活动运行时执行，执行期间拒绝新的开始。恢复先把新内容建在暂存目录里，全部完成后才替换进去。

其他操作都不独占目录。没有持久的根预留，没有参与者注册，没有跨根锁顺序。

### 5. 写入回执逐个文件还回撤销

内置文件工具（write、edit、apply-patch）每次写入上报一条回执：运行、路径、写前哈希、写后哈希。patch 里的每个文件有自己的可逆标记。

在重叠的运行里，某个文件的全部变化能被本运行的回执解释时可撤：第一条回执的写前哈希等于基线，最后一条回执的写后哈希等于结算时的内容。这个 patch 里的其他文件保持只读。

shell 命令、MCP 工具和外部 agent 不产生回执，它们在重叠运行里的写入保持只读。只带路径的事件不算回执。

这一步在第 1 到第 4 步之后交付。

## 影响

- 同一个仓库上的两个会话都能正常工作；在回执落地之前，重叠的轮次都不能撤销。回执落地后，只有 shell 命令或外部 agent 写的文件不能撤销。
- 每个不可逆的 patch 都带原因（`capacity`、`stop_unproven`、`overlap`、`path_unsupported`、`fidelity_unknown`），界面可以说明撤销为什么不可用。
- 停止未证实之后的晚到写入会进入下一轮的基线。下一轮的 diff 是对的；被取消那一轮的 diff 可能不完整，并且会标明。
- 重叠期间的归因从不靠猜，不把改动算给最后一个 agent 或收尾消息。
- 需要准确归因和完整撤销的运行使用托管根。

## 不做

- 独占预留、参与者子租约、应用内目录的隔离。如果出于安全而不只是归因的理由必须把某个写入者挡在目录外，再重新讨论。
- shell 命令和外部 agent 的回执。
- 检测 Cognia 之外的写入者。
