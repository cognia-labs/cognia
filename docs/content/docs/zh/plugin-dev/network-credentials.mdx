# 网络请求与已存储的凭据

`ctx.network` 需要 `network:fetch` 权限（上传使用 `network:upload`），目标地址
还必须满足 `networkAccess` 白名单。使用 SDK 的纯函数 `secretRef` 引用已存储的
凭据，由 Host 填入值：

```ts
import { secretRef } from "@cognia/plugin-sdk"

await ctx.secrets.store("provider-token", token) // 需要 secrets:write。
await ctx.network.post(
  "https://api.example.com/items?owner=alice@example.com",
  {
    authentication: { access_token: secretRef("provider-token") },
    note: userText,
  },
  {
    headers: { Authorization: secretRef("provider-token", { prefix: "Bearer " }) },
    query: { api_key: secretRef("provider-token") },
  }
)
```

引用必须用 `secretRef()` 创建。它返回 `{ $secretRef, prefix? }`，并在对象上加一个
Host 能识别、JSON 无法携带的品牌标记。手写的对象，或来自 webhook 载荷、模型输出的
对象，即使带有 `$secretRef` 键也只是普通数据：按普通字段检查，绝不会被解析。这样，
转发不可信 JSON 的插件不会把自己的 secret 发出去。

key 必须是非空字符串，prefix 必须是字符串。prefix 是插件自己写的文本，遵守下文的
字面凭据策略。Host 先完成 PII 清洗和目标白名单检查，再从**当前插件自己的**
`ctx.secrets` 命名空间读取并替换为 `prefix + value`。读取需要 `secrets:read`；
如果该权限需要逐次确认，确认提示会写明请求的方法和目标。引用无效、位置错误、
secret 不存在或为空时，在发送前报错；读取失败的请求也会被审计。

解析出的凭据不会进入审计、开发日志或限流键。服务端在响应（header、body、二进制
body）或错误里回显该值时，Host 会把它及其 URL、JSON、base64 编码形式替换为
`[REDACTED]` 后再交给插件；错误保留 name 和 code，只清理文本。两个例外：短于 8 个
字符的 secret 不做回显过滤（过滤这么短的字符串会误伤无关文本）；
`ctx.network.download` 保存的文件按原样写入。

引用只能作为以下凭据字段的值（忽略大小写）：`authorization`、
`proxy-authorization`、`x-api-key`、`api-key`、`apikey`、`api_key`、
`access-token`、`access_token`。支持的位置包括请求 header、
`NetworkRequestOptions.query` 参数，以及对象 body 中的凭据字段（包括嵌套对象；
以 JSON 字符串传入的 body 不能携带引用）。下载和上传的 header 同样支持引用。
其他字段和数组元素不能放置引用。Host 在 URL 清洗后追加 `query` 参数；
URL 自带参数和 `query` 中的字面字符串都遵守下述策略。

```json
{
  "permissions": ["network:fetch", "secrets:read"],
  "networkAccess": {
    "allowedDomains": ["api.example.com"],
    "literalCredentials": "inspect"
  }
}
```

`networkAccess.literalCredentials` 只接受两个值：

- `observe`：过渡期 Host 默认值。凭据位置中的字面字符串保持原样，每次发送
  通过 permission audit 记录 `literal-credential <header|query|body>:<name>`。
  插件开发日志在每个会话中对每个插件和字段仅警告一次，提示使用 `secretRef`。
  两种记录都只包含字段名，不包含值。所有字面凭据都会被标记，包括真实 token。
- `inspect`：对字面凭据正常执行 PII 脱敏；设置 `piiPolicy: "block"` 时拒绝发送。
  例如 `Bearer alice@example.com` 和 `?access_token=` 中的邮箱都会被脱敏。
  引用的 `prefix` 按同样方式检查；secret 本身原样填入。

此功能发布后的下一个版本将把 Host 默认值切换为 `inspect`（ES-05）。现在应将
已存储的 secret 改为引用，并显式启用 `inspect` 验证兼容性。内置 `feishu-auth`
在过渡期保留 JSON session record，使用默认 `observe`。Host 证明的 PKCE 字段、
现有内置 Feishu refresh 特例、未标记 form body 的处理和
`ctx.integrations.authenticatedRequest` 均保持原有行为。
`client_secret`、`refresh_token`、`private_token` 不属于通用凭据字段；
Host OAuth 的窄范围特例仍单独生效。

运行在 Node 插件宿主中的 JavaScript 插件行为相同：宿主用自己的线上标记跨进程保留
品牌。Python、WASM 和 iframe 插件都不能访问 `ctx.network`（公共 Python
`cognia.ctx` 的 catalog 未开放 `network`），所以没有 Python helper。
